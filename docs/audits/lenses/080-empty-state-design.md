# Lens 080 — Empty State Design Critic

**Distinct value:** Evaluates every empty state in the application: are they useful (guiding the user to take action) or decorative (generic "nothing here yet" messages)? Do empty states explain why the section is empty and what the user should do?

**Tenancy-critical:** Yes. New products start with empty everything. The empty-to-populated transition is the most critical part of onboarding. Poor empty states cause founder abandonment.

## Executive Summary

Foundry has approximately 20+ empty states across the codebase, ranging from excellent to useless. The `emptyState()` component function provides a basic pattern: centered text with an optional CTA button. The best empty states (agent provisioning, decision queue) explain what should be there and offer a clear next action. The worst empty states are generic text like "No data yet" with no guidance. The product has a secondary `emptyStateWithHint()` function that can display AI-generated contextual hints — this is a unique and valuable pattern that should be used more broadly. The biggest gap is that empty states do not differentiate between "you haven't set this up yet" and "this section is genuinely empty because your product hasn't generated data."

## Findings

### ES-01 Agent Provisioning Empty State Is Excellent
- **Severity:** (Positive Finding)
- **Description:** When no agents are provisioned, the agent roster shows: a robot emoji, "Provisioning..." heading, explanatory paragraph ("Your AI team hasn't been set up yet. Provision your 12 specialized agents..."), and a prominent "Provision Agents" button. This clearly explains the state, why it exists, and exactly what to do.
- **Evidence:** `src/routes/dashboard/agents.ts:143-150` — provisioning empty state with heading, explanation, and CTA.
- **Remediation:** N/A — use this as the model for other empty states.
- **Target Phase:** N/A

### ES-02 Generic "No data yet" Empty States Are Useless
- **Severity:** P2
- **Description:** Several empty states use generic text with no actionable guidance:
  - "No cohort data yet. Cohorts are created as users sign up." — Tells the user what creates data but not what they should do
  - "No founding story artifacts yet." — Decorative
  - "No digest data available." — No guidance
  - "No competitive signals detected recently." — Does not explain how to generate signals
  - "No published case studies yet. Check back soon." — Passive, no action
- **Evidence:** `src/views/components.ts:452` — cohort empty state. `src/views/components.ts:563` — journey empty state. `src/views/components.ts:603` — digest empty state. `src/views/components.ts:548` — competitive signals empty state. `src/routes/public/landing.ts:224` — case studies empty state.
- **Remediation:** Upgrade each empty state with: (1) context-specific explanation of why it is empty, (2) what will populate it, (3) a CTA to take the next action. Example: "No cohort data yet" becomes "Cohort analysis activates when your product starts tracking user signups. Connect your analytics integration to start." + [Set up integrations] button.
- **Target Phase:** 2

### ES-03 emptyStateWithHint() Is Underused
- **Severity:** P2
- **Description:** The `emptyStateWithHint()` function accepts an AI-generated `PageHint` and displays contextual guidance. This is a powerful pattern that exists but is only used on the audit page. It should be the default empty state for all data-dependent sections, where the AI system can provide guidance based on the product's current lifecycle stage.
- **Evidence:** `src/views/components.ts:940-949` — `emptyStateWithHint()` function. Only reference found is in the audit route.
- **Remediation:** Use `emptyStateWithHint()` for: decision queue empty state (hint based on product stage), competitive view empty state (hint about competitors), digest empty state (hint about first digest generation).
- **Target Phase:** 3

### ES-04 Decision Queue Empty State Has Good CTA
- **Severity:** (Positive Finding)
- **Description:** The decision queue empty state shows "No pending decisions." with a "Back to Dashboard" button. This is appropriate — decisions are generated by AI agents, so the user cannot create them manually. The CTA redirects to the primary view rather than leaving the user stranded.
- **Evidence:** `src/views/components.ts:339` — `emptyState('No pending decisions.', { label: 'Back to Dashboard', href: '/dashboard' })`.
- **Remediation:** Consider adding: "Your AI agents haven't generated any decisions yet. Decisions appear as agents identify opportunities or risks." to set expectations.
- **Target Phase:** 3

### ES-05 Empty States Do Not Distinguish "Not Set Up" vs "Genuinely Empty"
- **Severity:** P1
- **Description:** Empty states use the same visual treatment whether the feature hasn't been configured yet (action needed) or the section is empty because no data has been generated (patience needed). "No competitors configured" (user needs to add them) looks identical to "No competitive signals detected" (agents haven't run yet). These are fundamentally different states requiring different guidance.
- **Evidence:** Both `src/views/components.ts:517` and `src/views/components.ts:548` use the same `.text-muted` paragraph style for setup-required vs awaiting-data states.
- **Remediation:** Define two visual patterns: (1) "Setup required" — accent-colored border, icon, CTA button (like the agent provisioning state). (2) "Awaiting data" — subtle background, informational text, progress indicator or estimated time. Apply systematically across all empty states.
- **Target Phase:** 2

### ES-06 Portfolio Empty State Redirects — Could Be Better
- **Severity:** P2
- **Description:** When a founder has no products, the portfolio page redirects to `/onboarding`. This is functional but abrupt. A dedicated empty state on the portfolio page ("You haven't added any products yet. Start by connecting your first product.") would be more informative and less disorienting than a silent redirect.
- **Evidence:** `src/routes/dashboard/portfolio.ts:19` — `return c.redirect('/onboarding')`. Also `src/routes/dashboard/index.ts:129` — same redirect.
- **Remediation:** Show a proper empty state first: "Welcome to Foundry. Connect your first product to meet your AI team." with a prominent "Get Started" button linking to onboarding. This provides context before redirecting.
- **Target Phase:** 3

### ES-07 Settings Page Shows Raw Data Counts in Empty States
- **Severity:** P3
- **Description:** The settings page shows "No repositories connected." and "No competitors configured." as plain text in cards. These are correct but lack visual emphasis. The card structure makes empty text look like the card loaded incorrectly rather than being intentionally empty.
- **Evidence:** `src/views/components.ts:636` — "No repositories connected." in a card. `src/views/components.ts:647` — "No competitors configured." in a card.
- **Remediation:** Add a subtle icon or visual treatment to distinguish empty cards from loading states. Use `emptyState()` component with inline CTA: "No competitors configured. [Add competitors](/products/current/competitive)".
- **Target Phase:** 4

## Embarrassment Test
1. A new founder arrives at the competitive intelligence page and sees "No competitive signals detected recently." — they have no idea that they need to add competitors first, or that agents need to run a competitive scan. The empty state provides zero guidance.
2. An investor reviewing a multi-company portfolio sees identical empty states for "not configured" and "no data" — they cannot distinguish between products that need setup and products that are simply early stage.

## Recommendations (Priority Order)
1. Distinguish "setup required" vs "awaiting data" empty states visually (P1, Phase 2)
2. Add actionable guidance to generic "no data" empty states (P2, Phase 2)
3. Use `emptyStateWithHint()` for AI-powered contextual guidance (P2, Phase 3)
4. Add explanatory text to decision queue empty state (P3, Phase 3)
5. Replace portfolio redirect with proper empty state page (P2, Phase 3)
