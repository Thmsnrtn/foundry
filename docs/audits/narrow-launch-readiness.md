# Narrow Positioning Launch Readiness

Positioning: "Autonomous AI operations layer for solo SaaS founders running 1-5 products."

| Step | Implemented? | Notes |
|------|-------------|-------|
| Clerk signup | Yes | Standard OAuth flow |
| GitHub repo connect | Yes | OAuth with CSRF state validation |
| No-code path (URL only) | Yes | Alternative for non-GitHub users |

| Signal score on dashboard | Yes | 0-100 composite with anatomy dialog |
| 12 agents provisioned | Yes | Auto-provisioned during onboarding (v4 fix) |

| Decision queue | Yes | Gate 0-4 with scenario modeling |
| Risk state adaptation | Yes | Green/Yellow/Red with stressor tracking |

**Verdict: Fully functional.** A solo founder connecting one repo will get a complete, working experience.

## 3. Onboarding

| Aspect | Status |
|--------|--------|
| Signup to first audit | Works — 5-10 minutes including GitHub OAuth |
| Audit progress indication | Missing — synchronous 30-90s with no progress bar |
| First briefing | Generated by next cron cycle (could be hours after signup) |
| Onboarding tour | Exists — 10 steps via `src/services/ux/tour.ts` |

**Gap:** First briefing delay. A founder who signs up and gets an audit may wait hours for their first agent briefing. Consider triggering an immediate briefing after first audit.

## 6. Known Gaps Within Narrow Positioning

These matter even for the narrow "solo founder, 1-5 products" use case:

1. **No support contact** — Users who get stuck have nowhere to go
2. **No social proof** — Landing page has zero testimonials, logos, or user counts
3. **First briefing delay** — Could be hours after signup
4. **In-memory cost ceiling resets on deploy** — Cost tracking is lost on every deployment
5. **No error reporting service** — No Sentry or equivalent. Errors go to console logs only.
6. **Audit log capped at 500 with pagination** — v5 improved from 100, but no infinite scroll

## 7. Recommendation

**Is Foundry ready for friendly alpha with 3-5 trusted solo-SaaS-founder users?**

**Yes — with these 3 pre-launch actions:**

1. **Add a support email** — even just `mailto:thomas@foundry.so` in the footer and settings page. Users need a way to report issues.

2. **Set Fly.io secrets** — `ENCRYPTION_KEY`, `STRIPE_WEBHOOK_SECRET`, `ECOSYSTEM_SERVICE_KEY`, `OPENROUTER_API_KEY` must be configured before deploy.

3. **Test the onboarding flow end-to-end once** — sign up with a real GitHub repo, verify audit completes, verify agents provision, verify first briefing generates. One real run-through by the operator before inviting anyone.

The product works. The single-product experience is genuinely useful. The multi-product experience is functional. The security and reliability hardening from v3-v4 is real. Ship it to 3-5 trusted founders and learn.
