## Step-by-Step Transcript

1. Sam logs in. Portfolio view loads (5 companies). Sam clicks into Company A, then navigates to Settings.
2. Settings page renders. Subscription card: "Current Plan: Investor-Ready" badge.
3. "You have access to N features" — Investor-Ready has all features so N is the full count (~17 features).
4. **No upgrade button shown** (already at highest tier). "Manage Subscription" button visible.
5. Sam looks for per-company billing breakdown. **None exists.** The Subscription card shows only: tier name, feature count, and Manage Subscription.
6. **FRICTION**: Sam pays $399/mo for 5 companies. Wants to know cost-per-company and whether adding more companies changes the price. No information available.
7. Products section shows all 5 products with names and View links.
8. Sam clicks "Manage Subscription" -> Stripe portal.
9. Stripe portal shows: $399/month, last payment date, next billing date. **This is the only place Sam can see billing details.**
10. Sam returns to Foundry. Checks for invoice history. **No invoice section in Settings.**
11. Sam clicks through each product's Settings sections. Share Link and Ingest URL reference `firstProduct` (Company A) regardless of which product is selected via the switcher.
12. **FRICTION**: Sam wants to generate share links for each of the 5 companies for their board. Settings always generates the token for Company A (first product from DB query).
13. Sam navigates to the Wisdom Network section. Toggle shows current opt-in state. This is founder-level, not product-level. Toggle affects the `wisdom_network_opted_in` field on the `founders` table.
14. Sam checks the Investor/Advisor Access section. Share token generation POST to `/settings/generate-share` uses `LIMIT 1` on the founder's products — always the first product.
15. Sam wants to compare their billing with the feature usage across companies. No usage analytics exist in Settings.
16. Sam wants to see: how many AI tokens were consumed per company, how many SCP cycles ran, how many decisions were processed. **No per-company usage metrics in Settings.**
17. Sam navigates to `/api/founder-ops/export` (found via Quick Actions on founder-ops page). Gets a JSON export of all data — but this is the founder-ops admin export, not a billing/usage report.

## Cross-Company Awareness Check

- **Subscription**: Correctly founder-level. Tier badge is clear.
- **Products list**: Shows all 5. Correct.
- **Share Link / Ingest URL**: **BROKEN for multi-product** — always targets first product from DB. Critical for Sam who needs per-company share links for board presentations.
- **No per-company settings scope**: Product-specific settings (share token, ingest token) are embedded in a founder-level Settings page without product selection.

## Friction Events

| # | Severity | Category | Description |
|---|----------|----------|-------------|
| F038-1 | HIGH | Boundary Confusion | Share Link and Ingest URL generation always targets the first product in the database, ignoring the product switcher cookie. Sam cannot generate share links for companies 2-5. |
| F038-2 | HIGH | Missing Information | No per-company billing breakdown, no usage metrics, no cost-per-company analysis. |
| F038-3 | MEDIUM | Missing Feature | No invoice download or billing history within Foundry. Must use Stripe portal. |
| F038-4 | MEDIUM | Missing Feature | No usage analytics: AI tokens per company, SCP cycles, decision volume. |

## Verdict

**FAILED**

Billing transparency is insufficient for a portfolio operator paying $399/month. No per-company breakdown, no usage metrics, no invoice access. The share link generation bug affects daily operations. Sam cannot manage per-product settings from the Settings page.

## Recommendation

1. Fix share link and ingest URL generation to use the selected product (from cookie or URL param).
2. Add a billing breakdown card: "$399/mo Investor-Ready | 5 active companies | Next billing: May 1"
3. Add per-company usage metrics: AI tokens, SCP cycles, decisions processed, audit runs.
4. Add an in-app invoice history table with download links.
5. Move product-specific settings (share token, ingest token, competitors) to a per-product settings page.
