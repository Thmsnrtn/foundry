## Preconditions

Riley manages 12 companies. An investor requests a compliance export covering all portfolio companies -- agent activity, decision history, and audit scores. Riley needs fleet-wide data.

## Transcript

### Step 1: Navigate to Privacy & Data for export

Riley goes to Privacy & Data. The export section offers "Download JSON" for the currently selected company.

**Result:** PASS -- Export page loads.

### Step 2: Assess fleet-wide export needs

Riley needs to export data for all 12 companies. The Privacy export only covers 1 company at a time.

**Codebase finding:** `exportProductData(ctx.productId, 'json')` in privacy.ts is scoped to a single product. No fleet/batch export exists.

**Friction:** Riley must switch to each of the 12 companies and download 12 separate JSON files. Naming convention is `foundry-export-YYYY-MM-DD.json` (privacy.ts line 385) -- all 12 files will have the same filename, requiring manual renaming or downloading into different folders. The filename does not include the product name or ID.

**Result:** FRICTION (CRITICAL) -- No fleet-wide export. 12 individual downloads required. Filename collision (all named the same date-based name).

### Step 3: Export audit-log data

Riley needs agent activity logs for compliance. Navigates to Audit Log page.

**Codebase finding:** `audit-log.ts` line 77: `sql += ' ORDER BY created_at DESC LIMIT 100'`. The audit log is hard-capped at 100 entries with no pagination for bulk download. There is no "Export audit log" button.

Riley's 12 companies with 3+ months of data likely have thousands of audit log entries each. The 100-entry limit means less than a week of data for active companies.

**Result:** FRICTION (CRITICAL) -- Audit log capped at 100 entries with no bulk export. Compliance requirement for complete activity history is unmet.

### Step 4: Verify export includes decision history

Riley opens a downloaded JSON to check for decision history.

**Codebase finding:** The export payload (privacy.ts line 388-393) includes `exported_at`, `product_id`, `product_name`, plus whatever `exportProductData()` returns. Without inspecting the service, the export description (line 267) promises "metrics, briefings, decisions, customers, and agent configuration." Decision history should be included if the export is comprehensive.

**Result:** UNCERTAIN -- Decision history inclusion depends on `exportProductData()` implementation. The UI copy suggests it is included.

### Step 5: Cross-company boundary check

Riley exports data for Company A, switches to Company B, exports again. Each export contains only the respective company's data.

**Cross-company awareness check:** PASS. Export is correctly scoped via `ctx.productId`. No cross-company data in exports.

**Result:** PASS -- Export boundary is correct.
