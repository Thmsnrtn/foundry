**Codebase finding:** `src/routes/dashboard/privacy.ts` line 68 renders the privacy page. Layout sidebar at layout.ts line 289 includes `{ key: 'privacy', label: 'Privacy', href: '/privacy' }` under SYSTEM section.

**Result:** PASS -- Privacy page is accessible from sidebar.

### Step 2: Locate data export

Sam scrolls to "Section 3: Your Data" which shows "Export All Data" with a "Download JSON" button.

**Codebase finding:** privacy.ts line 267 renders the export section. The `<a href="/privacy/export">` link triggers GET `/privacy/export` (line 375) which calls `exportProductData(ctx.productId, 'json')`.

**Result:** PASS -- Export button is visible and clearly labeled.

### Step 3: Execute export

Sam clicks "Download JSON". A file `foundry-export-YYYY-MM-DD.json` downloads.

**Codebase finding:** The export handler (privacy.ts line 375-402) exports to JSON with Content-Disposition attachment header. The `exportProductData` function is in `src/services/privacy/consent.ts`. The exported payload includes `exported_at`, `product_id`, `product_name`, plus whatever `data` the function returns.

**Friction:** The export format is JSON only. No CSV option for auditors who need tabular data. The export is per-product, not fleet-wide -- Sam must repeat for each of 6 companies if the auditor needs all. No bulk export across fleet.

**Result:** FRICTION (MEDIUM) -- JSON-only export, no CSV. No fleet-wide bulk export.

### Step 4: Verify export completeness

Sam opens the JSON file and checks for agent activity logs, decisions, and metrics data.

**Codebase finding:** Without reading the full `exportProductData` implementation, the privacy page describes the export as including "metrics, briefings, decisions, customers, and agent configuration." However, the audit-log data (`agent_audit_log` table) is queried separately in `src/routes/dashboard/audit-log.ts` with a LIMIT 100. It is unclear whether the privacy export includes the full audit log or only the data described in the UI copy.

**Friction:** If agent activity logs are not included in the privacy export, Jordan-type compliance users (and Sam acting on behalf of auditors) cannot satisfy a "full agent activity log for 90 days" requirement in a single export. The audit-log route itself has a LIMIT 100 and no bulk download.

**Result:** FRICTION (HIGH) -- Audit log export completeness is uncertain. The UI's audit-log view limits to 100 entries with no bulk export. Compliance requirement for "all agent activity for 90 days" may not be satisfiable.

### Step 5: Cross-company boundary check

Sam switches to a different company and re-downloads the export. Verifies the new export contains only the new company's data.

**Codebase finding:** The export uses `ctx.productId` (from cookie-based product selection in `_shared.ts`). The `exportProductData` function takes `productId` as its first argument, scoping the export to a single company.

**Cross-company awareness check:** PASS. Each export is scoped to the currently selected product. No cross-contamination.

**Result:** PASS -- Export is correctly product-scoped.
