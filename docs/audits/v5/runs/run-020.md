# Run 020 — Riley (15-Company Power User) on Journey 05 (Remediation PR Review)

## Conditions
Fleet size: 15
Tier: Investor-Ready ($399)
Device: MacBook Pro, Arc browser
Network: Gigabit fiber

## Step-by-Step

1. **Riley wants to review all pending remediations across the fleet** → No fleet-level remediation view exists. Riley must check each product individually.
2. **Riley's approach** → Opens `/portfolio`. Plans to check each company for open remediations by clicking in and checking the sidebar nav badge (open_prs_count).
3. **Portfolio view** → 15 cards. No per-card remediation indicator. Riley cannot see which companies have open PRs from the portfolio. → Must click into each one.
4. **Riley starts clicking** → Company A: 0 PRs. Company B: 1 PR. Company C: 0. Company D: 0. Company E: 2 PRs. → After checking 5 companies (5 product switches, 5 page loads, 5 sidebar checks), Riley has found 3 remediation PRs.
5. **Riley reviews Company B's remediation** → `/agents/remediations` shows 1 item: add input validation on a webhook. Severity: MEDIUM. Agent: Sentinel. Riley clicks "View on GitHub" → PR looks good. Merges on GitHub. Returns, clicks Resolve. → 2 minutes.
6. **Riley switches to Company E** → 2 remediations. One security (HIGH: SQL injection fix), one performance (LOW: add database index). Riley resolves both. → 4 minutes.
7. **Riley continues scanning** → Companies F through O: 4 more PRs found across 10 product switches. Each switch: ~2 seconds load + sidebar check + navigate to remediations if badge shows. → 15 minutes of navigation overhead for 4 items.
8. **Total remediation review: ~30 minutes** → Found and reviewed 7 PRs across 15 companies. Actual review time: ~12 minutes. Navigation overhead: ~18 minutes.
9. **Riley's reaction** → "I just spent 18 minutes navigating to find 7 PRs. A single list would have taken 30 seconds to scan."

## Cross-Company Awareness
Did the user get confused about which company they were acting on? **YES** — Riley merged a PR on GitHub for Company E but then switched to Company F in Foundry before clicking "Resolve." Riley almost resolved Company F's unrelated remediation item instead. Caught it because the descriptions didn't match.

## Friction Events
- FRICTION-0066: CRITICAL — No fleet-level remediation queue. 15 separate remediation queues must be checked individually. 18 minutes of pure navigation overhead to find 7 items.
- FRICTION-0067: HIGH — Portfolio cards don't show open PR counts. The only way to know if a company has pending remediations is to switch to it and check the sidebar badge.
- FRICTION-0068: HIGH — Remediation resolve in Foundry is decoupled from GitHub merge. Riley must perform two actions (merge on GitHub + resolve in Foundry) for each PR. No webhook to auto-detect GitHub merge and update Foundry status.
- FRICTION-0069: MEDIUM — No batch "approve all" for low-severity remediations. Riley wanted to batch-approve all LOW-severity PRs but had to click into each one individually.
- FRICTION-0070: MEDIUM — Boundary confusion risk when switching between products mid-remediation-review. The remediation item ID doesn't change when you switch products, so the URL could show a stale context.

## Verdict: FAILED — fleet-scale remediation review is dominated by navigation overhead
## Would Recommend: Never — "O(n) navigation for O(1) information. Classic UI anti-pattern."
