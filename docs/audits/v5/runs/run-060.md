## Preconditions

Devon has 3 companies on Growth tier. Running VoiceOver on a laptop. Wants to add more companies toward the fleet target. Testing whether the scaling experience is accessible.

## Transcript

### Step 1: Tier gate for fleet scaling

Devon currently has 3 companies on Growth tier and wants to add a 4th.

**Codebase finding:** Growth tier ($199) supports multi-company, but the tier gate in `src/middleware/tier-gate.ts` may have a company count limit per tier. The pricing page (orientation doc) shows Solo=single company, Growth=multi-company, Investor-Ready=full fleet. However, the exact company limit for Growth is not visible in the orientation doc. If Growth allows unlimited companies, Devon can proceed. If Growth caps at a lower number, an upgrade prompt is needed.

**Friction:** The Growth tier's company count limit is not documented in the UI. Devon may not know whether adding a 4th company requires an upgrade to Investor-Ready.

**Result:** FRICTION (MEDIUM) -- Company count limits per tier are not clearly communicated.

### Step 2: Repeat add-company flow via screen reader

Devon attempts to add a new company using keyboard navigation.

**Codebase finding:** The "add company" flow requires navigating to Products (path unclear from sidebar), filling a form with company name, GitHub repo URL, and description. As established in run-053, the "Add Company" entry point is not discoverable from the dashboard at any fleet size. Devon must navigate to Settings or find the products management page.

**Friction (accessibility layer):** On top of the general discoverability problem (F-053-A), Devon faces the additional challenge that the product switcher (which is the most visible multi-company UI element) has no `aria-label` (F-059-A). The path to "add company" is even less accessible than for sighted users.

**Result:** FRICTION (HIGH) -- Add-company flow is inaccessible by compound effect: undiscoverable path + unlabeled interactive elements.

### Step 3: Risk state badge accessibility

After adding a company, Devon checks the risk state for each.

**Codebase finding (actual ARIA in components.ts):**
- `riskStateBadge()` at components.ts line 14-40 implements accessibility correctly:
  - Line 21-25: `stateIndicators` maps each color to a text+symbol combo: "GREEN checkmark", "YELLOW warning", "RED circle".
  - Line 33: `role="status" aria-label="Risk state: ${stateLabel}"` -- properly labeled.
  - The component comment references "A11Y-04: Pair each color with a distinct symbol so the risk state is not communicated by color alone (WCAG 1.4.1)."

**Positive finding:** Risk state badge is well-implemented for accessibility. Color is paired with symbols and text. ARIA role and label are correct.

**Result:** PASS -- Risk state badge has proper ARIA attributes, text equivalents for colors, and role="status".

### Step 4: Fleet view scaling accessibility

Devon navigates with VoiceOver at 3+ companies.

**Codebase finding:** The product switcher `<select>` at 3+ items is a native HTML select. VoiceOver handles native selects well -- announcing each option as Devon navigates. However, the lack of `aria-label` (F-059-A) persists. With more options, the unlabeled select becomes more confusing.

The sidebar (layout.ts) does not change based on fleet size. It always shows the same navigation structure for the currently selected product. There is no fleet-overview link or fleet-summary widget.

**Result:** FRICTION (HIGH) -- No fleet-level view accessible by screen reader. Single-company-at-a-time navigation with an unlabeled product switcher.

### Step 5: Keyboard shortcut for product switching

Devon looks for keyboard shortcuts to switch between companies.

**Codebase finding:** The command palette (Cmd+K) includes product-related items but not explicit "Switch to Company X" entries. The CMD_ROUTES array (layout.ts lines 124-152) lists page navigation routes, not product-switching actions. There is no keyboard shortcut to cycle between products.

**Friction:** J03 success criteria require "Keyboard navigation supports rapid company switching (j/k or arrow keys)." This does not exist. The only keyboard path is: Tab to product `<select>`, use arrow keys to select, Tab to submit (but the select auto-submits on change, so the page reloads immediately on arrow key press in the select).

**Result:** FRICTION (HIGH) -- No keyboard shortcuts for product switching. J03 success criterion for keyboard navigation unmet.

### Step 6: Cross-company boundary check

Devon switches between companies using keyboard navigation on the `<select>`.

**Cross-company awareness check:** PASS (technical). The native `<select>` with `onchange` submit correctly switches products and rescopes data. However, the `onchange` auto-submit means that pressing arrow keys in the select causes immediate page navigation -- Devon cannot browse options without triggering a switch.

**Friction:** Auto-submit on `<select>` change is hostile to keyboard users. VoiceOver users navigating the options list with arrow keys will trigger a page reload on each arrow key press, potentially switching to an unintended company.

**Result:** FRICTION (CRITICAL) -- Auto-submit on select change causes accidental product switches during keyboard navigation.
