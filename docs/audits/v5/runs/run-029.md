## Step-by-Step Transcript

1. Alex logs in. Navigates to Settings, then to Privacy & Data (`/privacy`).
2. Privacy page loads. Three sections visible: Data Sharing & Consent, Data Residency, Your Data.
3. Alex scrolls to Section 3: "Your Data." Two options: "Export All Data" (Download JSON button) and "Request Account Deletion."
4. Alex clicks "Download JSON" link (`/privacy/export`).
5. The `exportProductData` function runs against `ctx.productId` — the currently selected product.
6. **Export begins immediately** (synchronous GET request). No queue, no notification. The response streams back with `Content-Disposition: attachment; filename="foundry-export-2026-04-16.json"`.
7. Browser downloads the JSON file. Alex opens it.
8. **Export contains**: `exported_at`, `product_id`, `product_name`, `metrics` (metric_snapshots), `briefings` (scp_briefings), `decisions`, `customers`, `agent_config`.
9. **FRICTION**: Export is missing several data categories: stressor_history, audit_scores, competitive_signals, cohorts, lifecycle_state, failure_log, judgment_patterns, product_dna, founder data (email, name, preferences). The `exportProductData` function in `consent.ts` only exports 5 tables.
10. Alex compares this to the GDPR job in `gdpr.ts` which exports 15+ tables. The privacy page export is a subset.
11. **FRICTION**: No schema documentation included in the export. Raw database column names without explanation (e.g., `new_mrr_cents`, `cache_read_tokens`).
12. **FRICTION**: No scope selection. Alex cannot choose specific data categories — it is all-or-nothing for the current product.
13. **FRICTION**: No format choice. Only JSON is available. The privacy page mentions no CSV option despite the service accepting a `_format` parameter.
14. Alex checks whether the export covers all products. Since the route uses `ctx.productId`, only the currently selected product is exported. **No all-companies export option exists on the privacy page.**
15. The export file is ~50KB for 2 weeks of data. Download completes in under 1 second on NET-AVG.

## Cross-Company Awareness Check

- **Single product**: Only one product to export.
- **Export scope**: Tied to `ctx.productId` from the cookie-based switcher. If Alex had multiple products, they would need to switch products and re-export for each — the UI does not make this clear.
- **No all-companies option**: The GDPR job (`processDataExports`) exports by founder_id (all products), but the self-service privacy page export is per-product only.

## Verdict

**FAILED**

The export completes but is materially incomplete. A compliance export that omits stressor history, audit scores, decision patterns, and product DNA would fail a GDPR adequacy check. Alex gets a partial export but cannot verify it is complete because no manifest or schema is included.

## Recommendation

1. Align the self-service export with the GDPR job — export all 15+ tables.
2. Include a manifest listing all included data categories and any exclusions with justification.
3. Include schema documentation (column names, types, descriptions) in the export archive.
4. Add an "Export All Companies" option for multi-product founders.
5. Add CSV format toggle.
