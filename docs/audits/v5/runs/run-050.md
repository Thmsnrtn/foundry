## Step-by-Step Transcript

1. Morgan's session has been open for 3+ hours. JWT in the `__session` cookie is approaching expiration.
2. Morgan navigates to Privacy & Data (`/privacy`).
3. **ERR-AUTH injected**: Clerk JWT expires between the page load and the delete POST. The auth middleware parses the JWT from the cookie using regex-based extraction (per orientation doc — "Auth token extraction is regex-based, no cookie library").
4. Privacy page loads successfully (JWT still valid at page render time).
5. Morgan clicks "Delete My Data." Reads the modal. Clicks "Yes, Delete Everything."
6. POST to `/privacy/delete`. Auth middleware extracts the JWT. **JWT has expired.**
7. Clerk middleware behavior: fails to verify the expired token. The auto-provisioning logic (race condition handling) may or may not fire depending on the Clerk webhook state.
8. **Expected outcome**: Redirect to `/auth/login`. Morgan is logged out mid-deletion.
9. Morgan is redirected to the login page. No error message explaining why. No context preservation ("you were about to delete data").
10. Morgan logs back in. Clerk issues a new JWT. Morgan navigates to Privacy.
11. **Key question**: Was the deletion request processed before the auth failure? Morgan checks: the POST handler calls `scheduleDataDeletion(ctx.productId, 30)` AFTER auth middleware. If auth failed, the handler was never reached. **No deletion scheduled.**
12. Morgan clicks "Delete My Data" again. This time the JWT is fresh. POST succeeds. Deletion scheduled.
13. Redirect to `/privacy?success=deletion_scheduled`. Generic "Settings saved successfully" banner.
14. Morgan evaluates the deletion flow end-to-end:
    - **No product name in modal**: Confirmed defect.
    - **No confirmation email**: Confirmed.
    - **No Stripe cancellation**: Confirmed.
    - **No agent shutdown**: Confirmed.
    - **No GitHub revocation**: Confirmed.
    - **No deletion status page**: Confirmed.
    - **No cancellation mechanism**: Confirmed.
15. Morgan checks the legal page. Privacy policy mentions: "Request account deletion from Settings. 30-day grace period, then permanent deletion."
16. **FRICTION**: The privacy policy promises "account deletion from Settings" but Settings has no account deletion. The privacy page has product-level deletion. These are different things, and the legal text does not match the UI.
17. Morgan examines the `deletion_requests` table structure (from migration 005): has `status`, `confirmed_at`, `confirmation_token`. This implies a confirmation email flow that was designed but never implemented in the UI.
18. Morgan notes: "The schema was designed for GDPR-grade deletion with confirmation tokens and status tracking. The UI shortcuts this with a direct `scheduleDataDeletion` call that bypasses the designed flow entirely."

## Cross-Company Awareness Check

- **Single product**: No cross-company issues.
- **Deletion scope**: Morgan understands it is product-level. But the legal text promises "account deletion."
- **Auth edge case**: Expired JWT during a destructive operation does not produce data corruption (auth blocks the request). This is actually correct behavior, though the UX is poor.

## Verdict

**FAILED**

Morgan identifies a critical gap between the designed system (schema with confirmation tokens, GDPR-grade deletion job) and the implemented UI (direct `scheduleDataDeletion` call that bypasses the designed flow). The legal text promises account deletion that does not exist. The auth edge case reveals poor session management during destructive operations.

## Recommendation

1. Wire the `deletion_requests` table to a proper account deletion flow: Settings -> "Close Account" -> Confirmation email with token -> User confirms -> 30-day grace -> Hard delete.
2. Update the privacy policy to match the actual implemented features.
3. For destructive operations (deletion), use a short-lived action token embedded in the form, not just the session JWT. This prevents auth-expiration mid-action failures.
4. Show a specific deletion confirmation page with timeline, not a generic success banner.
5. Cancel Stripe subscription as part of the deletion flow.
