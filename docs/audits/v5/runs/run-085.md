# Run 085 — Taylor (P07) x Full Org Deletion (J10)

**Persona:** Taylor — returning user after 6-week absence, Growth tier, 1 company
**Journey:** Full organization deletion (churn path)
**Severity Baseline:** Taylor returned, found the dashboard overwhelming, and is considering quitting.

---

## Simulation Transcript

### Step 1: Taylor's emotional state on return

Taylor returned after 42 days, found 23 unprocessed decisions, no catch-up summary, no clarity on what agents did, and is still being charged. This is a classic churn moment. Taylor may decide: "This isn't helping. I'll just delete everything."

### Step 2: Taylor navigates to deletion

Taylor goes to `/privacy`. The "Delete My Data" button is visible. Taylor clicks it. The modal appears.

**From Taylor's perspective:** The modal says "permanently schedule deletion of all your product data including metrics, briefings, decisions, and agent logs. This cannot be undone."

Taylor pauses — "Wait, should I export first?" The modal includes a link: "We recommend exporting your data before proceeding." Good UX for the export reminder.

### Step 3: Taylor exports first, then deletes

Taylor clicks the export link, downloads the JSON (incomplete as noted in Run 084), then returns to the deletion modal and clicks "Yes, Delete Everything."

### Step 4: Taylor expects billing to stop

Deletion is scheduled. Taylor expects no more charges. But as documented in Run 080:
- Stripe subscription is NOT cancelled
- Taylor will be charged again on the next billing cycle
- Taylor must separately go to Settings > Manage Subscription > Cancel via Stripe

**Taylor's reaction:** "I just deleted my data and I'm still being charged? This is hostile."

### Step 5: Taylor checks for deletion confirmation

The page redirects to `/privacy?success=deletion_scheduled`. A green banner says "Settings saved successfully." (This is the generic success banner, not a deletion-specific message.)

**Codebase evidence:** `src/routes/dashboard/privacy.ts` lines 89-93 — the success banner is generic. The `deletion_scheduled` value is passed as a query param but the banner template only checks for truthiness, not for the specific value.

No email confirmation sent. No deletion receipt. No "your data will be deleted in 30 days" countdown.

### Step 6: Taylor expects agents to stop

SCP agents continue running. Taylor may see new briefings and decisions appearing even after scheduling deletion. This is contradictory and confusing.

### Step 7: Taylor checks for grace period recovery option

Journey 10 specifies a 30-day grace period with recovery. The `processScheduledDeletions` function does wait 30 days before executing. But there is no UI to:
- See that deletion is pending
- See the countdown
- Cancel the deletion
- Recover during the grace period

Taylor would need to... contact support? There is no self-service recovery.

---

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | CRITICAL | **Billing continues after deletion scheduled** (same as Run 080). Taylor will be charged again. This is the most hostile outcome for a churning user. |
| 2 | CRITICAL | **Agents continue running after deletion scheduled** (same as Run 080). |
| 3 | HIGH | **Generic success message, not deletion-specific.** "Settings saved successfully" is misleading for a destructive action. Should say "Deletion scheduled. Your data will be removed after April 16, 2026." |
| 4 | HIGH | **No confirmation email or deletion receipt.** Taylor has no proof that deletion was requested. |
| 5 | HIGH | **No recovery path during grace period.** If Taylor changes their mind within 30 days, there is no self-service cancel/undo. |
| 6 | MEDIUM | **Export is incomplete** (same as Run 084). Taylor's last export before deletion is missing critical data. |
| 7 | HIGH | **Returning users are high-churn-risk and get zero retention treatment.** No "welcome back" experience, no "here's what you missed," no "we noticed you were away — want a catch-up briefing?" The absence-to-deletion pipeline is entirely frictionless in the wrong direction. |

## Cross-Company Awareness Check

Not applicable — single company. But the deletion system operates per-product, not per-organization, so a multi-product Taylor would need to delete each product individually.

## Verdict: JOURNEY FAILED — Deletion is cosmetic (billing continues, agents run, no receipt, no recovery)
