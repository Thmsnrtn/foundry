## Step-by-Step Transcript

1. Riley logs in. Portfolio view shows 15 companies. Company #12 is being sold — Riley needs to remove it from the fleet.
2. Riley clicks Company #12 from the portfolio grid. Dashboard loads.
3. Riley navigates to Settings. Scans for a "Remove from fleet" or "Retire" option.
4. **No retirement option.** Products section lists all 15 products. No per-product actions besides "View."
5. Riley navigates to Privacy (`/privacy`). Sees "Delete My Data."
6. Riley reads the modal. "This will permanently schedule deletion of all your product data."
7. **Riley's concern**: Company #12 is being sold. The buyer needs the historical data. Deletion would destroy the deal's data room.
8. Riley wants to: (a) export Company #12's data, (b) disconnect it from Foundry's SCP monitoring, (c) keep the data for 90 days for the deal, (d) then clean up.
9. **Export first**: Riley clicks "Download JSON." Gets a partial export (5 tables). Missing: audit scores, competitive signals, cohort data, SCP briefings.
10. **FRICTION**: Partial export is insufficient for a data room. The buyer's due diligence team needs full audit history.
11. **Disconnect**: Riley looks for a way to disconnect GitHub. Settings shows GitHub repo URL but no disconnect/revoke button.
12. **Stop agents**: Riley checks Agents page. 12 agents listed. No pause/stop button. No per-company agent control.
13. Riley realizes: there is no clean way to retire a company from the fleet. The only option is full deletion, which destroys data the buyer needs.
14. Riley considers a workaround: manually revoke the GitHub OAuth token at github.com. This would break the integration but not remove the product from Foundry.
15. Riley goes to GitHub settings -> Applications -> Revokes Foundry's access for the Company #12 repo.
16. Returns to Foundry. Company #12 still shows in portfolio. SCP agents still scheduled (but will fail on GitHub-dependent operations).
17. **Workaround achieved**: Agent GitHub operations fail silently (no retry/circuit breaker per orientation doc), but AI analysis and metric tracking continue.
18. **FRICTION**: This is a hack, not a feature. The product appears unhealthy in the portfolio because failed GitHub operations degrade scores.
19. Riley concludes: proper company retirement requires feature work that does not exist.

## Verdict

**FAILED**

Company retirement for a sale/handoff is impossible through Foundry. Riley must use workarounds (manual GitHub revocation) that degrade the portfolio view. No data export is comprehensive enough for M&A due diligence.

## Recommendation

1. Add "Retire Company" flow: stops SCP agents, disconnects integrations (with API-level token revocation), moves product to "archived" state, removes from active portfolio.
2. Archived companies visible in a separate "Archived" section with read-only access.
3. Comprehensive export endpoint for M&A handoff including all audit history, SCP briefings, and agent logs.
4. Add per-company GitHub disconnect button in product-level Settings.
