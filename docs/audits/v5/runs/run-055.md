**Result:** FRICTION (HIGH) -- Network Intelligence is per-product, not cross-fleet.

### Step 4: DB latency impact assessment

Under ERR-DB conditions, every page load involves multiple DB queries.

**Codebase finding:** `_shared.ts` line 59-134 makes 7+ parallel DB queries on every dashboard page load: `getProductsByOwner`, `getLifecycleState`, `getProductDNA`, `getNextAction`, `getUnreadNotifications`, `getUnreadCount`, `getUnseenMilestones`, `getTourState`, plus a remediation PR count query. With 5-10 second latency per query, even parallelized, the minimum page load time would be 5-10 seconds.

**Friction:** No timeout on DB queries. No circuit breaker. No loading skeleton or progressive rendering. The server blocks until all queries complete, then sends the full HTML response. User sees a blank page for 5-10 seconds.

**Result:** FRICTION (CRITICAL) -- No DB timeout, no progressive loading. 5-10 second blank page under DB latency.

**Result:** PASS (boundary) / FAIL (journey) -- Boundaries are correct but the journey goal is unachievable.
