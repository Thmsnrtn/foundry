# Run 089 — Casey (P08) x Compliance Export (J09)

**Persona:** Casey — VP Engineering evaluating for startup studio, Solo trial
**Journey:** Compliance export (GDPR-style)
**Severity Baseline:** Casey's CTO will ask "can we get our data out?" as part of the security review.

---

## Simulation Transcript

### Step 1: Casey evaluates data portability as part of security review

For enterprise adoption, Casey's CTO will require:
1. Data can be exported at any time (no lock-in)
2. Export is complete and machine-readable
3. Export includes all data the platform holds about the organization

### Step 2: Casey navigates to export

Casey goes to `/privacy` and sees the "Export All Data" section with "Download JSON" link. Casey clicks it.

### Step 3: Casey examines the export structure

The JSON export downloads immediately. Casey inspects it:
```json
{
  "exported_at": "...",
  "product_id": "...",
  "product_name": "...",
  "metrics": [...],
  "briefings": [...],
  "decisions": [...],
  "customers": [...],
  "agent_config": [...]
}
```

**Casey's security review notes:**
- Export is per-product, not per-account. For 12 products, Casey would need 12 separate exports.
- No schema documentation in the export. The format is undocumented.
- Agent activity logs are missing. The CTO would ask: "What actions did the AI take on our codebase?"
- Customer data is included (good for portability) but the export format is raw database rows with no field descriptions.

### Step 4: Casey checks for export completeness

Casey cross-references the export against visible data in the dashboard:
- Signal scores visible on dashboard -- not in export (only in briefings as signal_score field)
- Stressor reports visible on dashboard -- **not in export**
- Audit results visible at `/audit` -- **not in export** (audit_scores missing)
- Agent health scores visible at `/agents` -- **not in export**
- Remediation PRs visible at `/agents/remediations` -- **not in export**

**Casey's conclusion:** "The export is maybe 30% of what the platform actually holds about our product. This fails the security review."

### Step 5: Casey evaluates export for multi-product scenario

For 12 products, Casey would need to:
1. Select each product via the product switcher
2. Navigate to `/privacy` for each
3. Download JSON for each
4. Manually combine into a single archive

No bulk export. No "export everything for all my products" option.

### Step 6: Casey checks for CSV support

No CSV option. Casey's CTO might want to share export data with a non-technical auditor who cannot parse JSON. Same finding as Run 079.

---

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | CRITICAL | **Export is approximately 30% complete.** Missing: agent activity logs, audit scores, stressor history, signal history, remediation records, gate events, team data, consent records. |
| 2 | HIGH | **Per-product export only.** For 12 products, Casey must export 12 times. No bulk or account-wide export. |
| 3 | HIGH | **No schema documentation in export.** Field names are database column names with no descriptions. An external auditor cannot interpret the export without Foundry-internal knowledge. |
| 4 | HIGH | **No CSV format** (same as Run 079). |
| 5 | MEDIUM | **Export link is not time-limited or authenticated.** The `/privacy/export` endpoint returns data via a synchronous GET request. If the URL is bookmarked and session is valid, data downloads without additional confirmation. |
| 6 | HIGH | **Security review would fail.** "Can we get our data out?" answer is "partially, with significant effort, in an undocumented format." This blocks enterprise adoption. |

## Cross-Company Awareness Check

The per-product export ensures data isolation: exporting Company A only returns Company A's data. However, there is no verification that the export does not inadvertently include cross-company patterns from the `decision_patterns` table (which has no access controls). The export does not include `decision_patterns`, so this specific leak does not occur in the export — but the underlying data pollution exists in the live platform.

## Verdict: JOURNEY FAILED — Export exists but is critically incomplete for enterprise security review
