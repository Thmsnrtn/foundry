# Run 077 — Jordan (P06) x Company Retirement (J07)

**Persona:** Jordan — compliance-minded fintech founder, Growth tier, 1 company
**Journey:** Company retirement / archival
**Severity Baseline:** Jordan treats audit trails as load-bearing infrastructure.

---

## Precondition Check

Jordan has 1 company. Journey 07 requires 2+ companies (retiring one from a fleet). This is the edge case: fleet size 1 -> 0 (retiring the only company).

Jordan's compliance context makes this nuanced: even if Jordan is not retiring, they need to know the retirement process is auditable and that archived data remains accessible for regulatory review.

---

## Simulation Transcript

### Step 1: Jordan looks for "Retire Company" in settings

Jordan navigates to `/settings`. The settings page shows:
- Subscription card
- Products list
- Wisdom Network toggle
- Investor/Advisor access
- Metric Ingest

**No "Retire Company" button exists.** No company lifecycle management controls.

**Codebase evidence:** `src/routes/dashboard/settings.ts` — the entire settings route has no retirement, archival, or company lifecycle controls. Products are listed with a "View" link to their audit page and an "+ Add Product" button, but no "Retire" or "Archive" option.

### Step 2: Jordan checks privacy settings

Jordan navigates to `/privacy`. This page has:
- Data Sharing & Consent toggles
- Data Residency settings
- Export All Data (JSON download)
- Request Account Deletion (deletes product data, not retirement)

The "Delete My Data" button opens a modal that says "permanently schedule deletion of all your product data." This is deletion, not retirement. There is no middle ground.

**Codebase evidence:** `src/routes/dashboard/privacy.ts` lines 273-285 — only hard deletion, no "archive and keep read-only" option.

### Step 3: Jordan examines the product status model

The schema supports `status IN ('active', 'paused', 'archived')` (`src/db/schema.sql` line 37). The SCP provisioner has a `deprovisionSCP()` function that sets `scp_status='archived'` and pauses agent instances. But there is no UI to trigger this.

**Codebase evidence:** `src/services/scp/provisioner.ts` lines 191-200 — `deprovisionSCP()` exists but is never called from any route handler. It is dead code from the UI perspective.

### Step 4: Jordan checks if archived products are accessible

The tenant middleware explicitly blocks archived products: `if (row.status === 'archived') { ... }` returns 404 (`src/middleware/tenant.ts` line 44-45). So even if a product were archived via direct DB manipulation, it would be completely inaccessible — not "read-only accessible" as Journey 07 requires.

### Step 5: Jordan checks billing impact

No billing adjustment occurs on product status change. The Stripe billing model is per-founder-tier, not per-product-count. The `createCheckoutSession` function takes a tier (solo/growth/investor_ready) but has no per-company pricing component. Retiring a company would not change the bill.

**Codebase evidence:** `src/services/billing/stripe.ts` — checkout sessions are tier-based, not fleet-size-based.

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | CRITICAL | **No retirement flow exists in the UI.** `deprovisionSCP()` exists in the provisioner but is unreachable from any route. There is no "Retire Company" button anywhere. |
| 2 | CRITICAL | **Archived products return 404.** The tenant middleware treats `status='archived'` as nonexistent. There is no read-only archive mode. Data becomes completely inaccessible, which fails Jordan's regulatory requirement to access historical agent logs post-retirement. |
| 3 | HIGH | **Only deletion or full operation.** The privacy page offers "Delete My Data" (hard delete after 30 days) or nothing. No middle ground between "fully active" and "permanently deleted." |
| 4 | HIGH | **No billing adjustment on product count change.** Billing is tier-based, not per-company. Journey 07 expects billing to decrease by one unit — but the pricing model does not support this. |
| 5 | MEDIUM | **`deprovisionSCP()` is dead code.** The function exists, pauses agents, and sets archived status, but nothing calls it. |
| 6 | HIGH | **Compliance gap: archived data inaccessible.** Jordan's auditor needs access to historical agent activity logs for at least 90 days post-retirement. The current model makes archived data completely unreachable. |

## Cross-Company Awareness Check

No cross-company boundary concern in this run — Jordan has only 1 company. However, if Jordan had multiple companies and retired one, the `getProductsByOwner` query in `src/db/client.ts` line 77 filters out archived products (`status != 'archived'`), which means the product vanishes from the fleet view entirely. No archive indicator, no historical access.

## Verdict: JOURNEY FAILED — No retirement flow, only deletion or inaccessibility
