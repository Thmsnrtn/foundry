## Step-by-Step Transcript

1. Alex logs in. Navigates to Privacy & Data (`/privacy`).
2. Privacy page loads. Section 3: "Your Data" shows "Request Account Deletion" with a red "Delete My Data" button.
3. Alex clicks "Delete My Data." A modal appears:
   - Title: "Confirm Data Deletion"
   - Body: "This will permanently schedule deletion of all your product data including metrics, briefings, decisions, and agent logs. This cannot be undone."
   - Recommendation: "We recommend exporting your data before proceeding."
   - Buttons: "Cancel" and "Yes, Delete Everything"
4. **CRITICAL FRICTION**: The modal says "product data" not "organization/account." Alex wants to delete their entire Foundry account — not just one product's data. The `scheduleDataDeletion` function acts on a single `productId`, not the founder account.
5. **CRITICAL FRICTION**: The modal does not say which product is being deleted. No product name visible.
6. Alex notices the modal says "This cannot be undone" — but the code actually has a 30-day grace period. The UI misrepresents the deletion timeline.
7. Alex clicks "Yes, Delete Everything." POST to `/privacy/delete` runs `scheduleDataDeletion(ctx.productId, 30)`.
8. Redirect to `/privacy?success=deletion_scheduled`. Alex sees a green "Settings saved successfully" banner. **Not a deletion confirmation banner** — the success message is generic.
9. **FRICTION**: No confirmation email sent. No deletion receipt. No timeline shown ("your data will be deleted in 30 days").
10. Alex checks: is the Stripe subscription cancelled? **No.** `scheduleDataDeletion` only writes an audit log entry. No Stripe cancellation is triggered.
11. Alex checks: are SCP agents stopped? **No.** `scheduleDataDeletion` does not stop agents. They continue running against data scheduled for deletion.
12. Alex checks: is the GitHub token revoked? **No.** Token revocation only happens in the `processScheduledDeletions` function when it nullifies `github_access_token`, but the token is not revoked at the GitHub API level.
13. Alex navigates to the Dashboard. Everything still works. No indicator that deletion is pending.
14. Alex goes back to Privacy page. **No indicator that a deletion is pending.** No way to cancel it. The audit log entry is not surfaced in the UI.
15. After 30 days (simulated): `processScheduledDeletions` runs via cron. It deletes data from 14 tables, sets product status to `deleted`, nullifies the GitHub token. But the `founders` table row is NOT deleted — this is product deletion, not account deletion.
16. Alex's Stripe subscription continues to be charged. The founder account still exists with 0 products.

## Cross-Company Awareness Check

- **Deletion scope**: `/privacy/delete` targets a single product (`ctx.productId`). To delete all companies, a multi-product founder would need to repeat this for each product — and even then, the founder account and Stripe subscription persist.
- **CRITICAL**: No organization-level deletion exists. The privacy page deletion is product-scoped, not account-scoped. The `processAccountDeletions` function in `gdpr.ts` handles full account deletion (founders table, all products, all child data, webhook cleanup) — but there is no UI path to trigger it. The `deletion_requests` table exists but no route creates records in it.

## Verdict

**FAILED**

Full organization deletion is not achievable through the UI. The "Delete My Data" button only schedules product-level data deletion without cancelling billing, stopping agents, revoking integrations, or providing confirmation. A GDPR-grade account deletion job exists in code but is unreachable from the UI.

## Recommendation

1. Create an "Account Deletion" flow separate from per-product data deletion. Use the existing `deletion_requests` table and `processAccountDeletions` job.
2. Route: Settings -> Delete Account -> Confirmation (type account email) -> Stripe cancellation -> Agent shutdown -> Token revocation -> 30-day grace -> Hard delete.
3. The delete modal MUST name the product and distinguish product deletion from account deletion.
4. Send a confirmation email with deletion timeline and cancellation instructions.
5. Show a prominent banner on all pages when deletion is pending, with a cancel button.
