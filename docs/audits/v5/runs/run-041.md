2. Portfolio route passes tier gate. `getProductsByOwner` returns 15 products.
3. `computeSignal` runs for all 15 products in parallel. Each signal computation involves multiple DB queries (stressors, metrics, lifecycle state, decisions). **At 15 products, this is 75+ parallel DB queries.**
4. On NET-FAST with Turso, each query is ~10-30ms. But 75+ queries in parallel may hit connection pooling limits. Estimated load time: 3-6 seconds.
5. Portfolio page renders. Grid of 15 cards sorted by Signal score. On 1920x1080, this creates a 3-column grid with 5 rows. All visible without scrolling.
6. **Riley's immediate reaction**: "This is just 15 cards. Where's the fleet intelligence?"
7. Riley scans for keyboard shortcuts. **None.** No j/k navigation, no Enter to drill in, no Escape to go back. Mouse-only.
8. Riley tries Cmd+K. Command palette opens. Types "fleet" — no results. Types "cross" — no results. Types "portfolio" — finds "Portfolio" link which is the current page.
9. Riley checks the HTML source (9/10 technical). No HTMX attributes for dynamic updates. No WebSocket for real-time fleet data. Static server-rendered HTML.
10. Riley wants to see: "Which of my 15 companies had MRR decline this week?" No such view exists.
11. Riley wants: "Show me the 3 companies with the most active stressors." No sortable table. Only Signal-score-sorted cards.
12. Riley clicks into Company #1. Checks dashboard, notes metrics. Presses browser back. Portfolio reloads (full page re-render, 75+ queries again). **No caching.**
13. Riley clicks Company #2. Repeat. Back. Portfolio reloads again. **O(n) triage with full page reload between each.**
14. **FRICTION**: At 15 companies, morning triage should take 15 minutes. With 6-second portfolio loads and no keyboard navigation, each company takes ~45 seconds to check. 15 x 45s = 11 minutes just for portfolio navigation, before actually doing anything.

16. Riley considers building their own dashboard against the Foundry data. Checks for an API key mechanism. The `portfolios` table has an `api_key` field with `pfk_*` format — but this is for investor/portfolio API access, not for the founder's own fleet.
17. No fleet intelligence exists. No batch operations. No keyboard shortcuts. No real-time updates.

## Verdict

**FAILED**

Cross-company intelligence is nonexistent at F15. The portfolio view is a static grid that does not scale to Riley's triage needs. No keyboard navigation, no batch operations, no caching, and O(n) click-through required for each company. Riley would abandon Foundry in favor of a spreadsheet.

## Recommendation

1. Build a fleet triage table: sortable columns for company name, Signal, MRR, delta, stressor count, pending decisions. Keyboard navigable.
2. Add batch operations: "Approve all Gate 0-1 decisions across fleet," "Dismiss all info-level signals."
3. Add Cmd+K fleet navigation: type company name to jump to it.
4. Cache Signal scores with a 5-minute TTL. Pre-compute fleet aggregates in a cron job.
5. Add a fleet API endpoint for external dashboard integration.
