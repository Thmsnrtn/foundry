## Precondition Check

Jamie has 2 companies on Growth tier. J06 requires 3+ companies for meaningful cross-company intelligence. Growth tier does not include `multi_product` — wait, checking: `multi_product` is Investor-Ready only. But Jamie on Growth already has 2 products. The `multi_product` gate only applies to the portfolio view. Individual product views work on Growth.

Actually, re-checking: the portfolio route (`/portfolio`) requires `requireTier('multi_product')` which is Investor-Ready only. Jamie on Growth cannot access the portfolio view.

8. Jamie tries the command palette (Cmd+K). Types "dashboard" — link goes to `/dashboard` which will redirect again.
9. Jamie tries `/settings` — this does NOT require `multi_product` gate. Settings loads with the first product selected automatically.

11. Jamie clicks "View" on the second product — this goes to `/products/{id}/audit` which loads successfully.

16. No cross-company intelligence feature exists for Growth tier founders with 2 products.

- **No cross-company view**: Even if the portfolio gate were removed, the portfolio view shows Signal scores per company — it is not cross-company intelligence.

## Verdict

**BOUNDARY_CONFUSION**

Jamie is locked out of the dashboard due to a tier-gating inconsistency: Growth allows creating multiple products but does not allow viewing the portfolio needed to switch between them. This is a critical broken state.

## Recommendation

1. If Growth tier can create multiple products, Growth tier must be able to access the portfolio view (or at minimum, a product switcher that does not require the portfolio route).
2. Alternatively, block product creation at Growth tier and only allow it at Investor-Ready.
3. Add a direct product-switching mechanism that does not require the portfolio route (e.g., a dropdown in the header that sets the cookie directly).
4. Build actual cross-company intelligence: correlation detection, shared stressor patterns, MRR comovement analysis.
