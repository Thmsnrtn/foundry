# Run 034 — Jamie x J09 (Compliance Export)

## Conditions

| Axis | Value |
|------|-------|
| Persona | Jamie (Two-product founder, non-technical, 4/10 technical) |
| Journey | J09 — Compliance Export (GDPR-Style) |
| Fleet size | F2 (2 companies) |
| Network | NET-FAST |
| Screen | SCR-LAP (1440x900) |
| A11Y | A11Y-OFF |
| Account | ACCT-EST (2+ weeks SCP data) |
| Tier | TIER-GROW ($199) |
| Error | ERR-DB (Turso latency spike 5-10s) |

## Step-by-Step Transcript

1. Jamie logs in. Navigates to `/settings` (bypassing portfolio gate).
2. Navigates to Privacy & Data (`/privacy`).
3. Privacy page requires loading consents, timestamps, and residency settings — 3 parallel DB queries.
4. **ERR-DB injected**: Turso responds in 5-10 seconds per query. Privacy page takes ~10 seconds to render.
5. Jamie waits. No loading indicator — server-rendered HTML means the browser shows a blank/loading state until the full response arrives.
6. Page finally loads. Jamie scrolls to "Export All Data."
7. Jamie clicks "Download JSON" link.
8. `exportProductData` runs 5 parallel queries against the slow database. Each takes 5-10s. Total wait: ~10 seconds.
9. **FRICTION**: No progress indicator. Browser shows a download spinner but no ETA or status. On NET-FAST the bottleneck is the DB.
10. Download completes. Jamie opens the JSON file.
11. **FRICTION**: Jamie is non-technical (4/10). JSON format is not user-friendly. Sees nested objects with keys like `new_mrr_cents`, `cache_read_tokens`, `risk_state`. Cannot interpret the data.
12. Jamie wanted a spreadsheet-compatible format. Only JSON is available from the UI.
13. Jamie checks: which product was exported? The JSON includes `product_id` and `product_name` — the first product (scheduling widget). Jamie wanted to export both products.
14. Jamie would need to switch to the second product and export again. But cannot switch products due to the portfolio gate issue.
15. **FRICTION**: No all-products export. No indication on the privacy page of which product is being exported until after download.

## Cross-Company Awareness Check

- **Export targets wrong product**: Jamie wanted to export both products. The export only covers the first (default) product. No product name displayed before clicking "Download."
- **No multi-product export**: Each product must be exported individually, requiring product switching (which is broken for Growth tier).
- **Export header**: The JSON file includes `product_name` which clarifies after the fact, but Jamie wanted to choose beforehand.

## Friction Events

| # | Severity | Category | Description |
|---|----------|----------|-------------|
| F034-1 | HIGH | Boundary Confusion | Export does not indicate which product will be exported before the user clicks download. Product name only visible in the downloaded file. |
| F034-2 | HIGH | Accessibility | JSON-only export is unusable for non-technical founders. No CSV or human-readable format. |
| F034-3 | MEDIUM | Performance | Under DB latency (ERR-DB), privacy page takes 10s to load and export takes another 10s. No loading indicator or progress bar. |
| F034-4 | MEDIUM | Multi-Product Gap | Cannot export all products at once. Must switch products and re-export — but product switching is gated. |
| F034-5 | LOW | UX | Download link is a plain `<a href>` — no confirmation, no "preparing export" state. |

## Verdict

**FAILED**

Jamie gets an export but for the wrong product, in an unreadable format, with no way to export the second product. The journey fails on scope, format, and product selection.

## Recommendation

1. Show "Exporting data for: **Scheduling Widget**" on the privacy page before the download link.
2. Add CSV export format — essential for non-technical founders.
3. Add an "Export All Products" option.
4. Add a loading/progress state for the export (use HTMX or redirect to a "preparing" page).
