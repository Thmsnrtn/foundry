# Run 093 — Devon (P09) x Settings & Billing Multi-Company (J08)

**Persona:** Devon — blind founder, screen reader + keyboard user, Growth tier, 3 companies
**Journey:** Settings and billing with multi-company pricing
**Severity Baseline:** Devon manages 3 companies. Billing clarity must be accessible via screen reader.

---

## Simulation Transcript

### Step 1: Devon navigates to Settings

Devon uses VoiceOver. The settings page renders as server-rendered HTML. VoiceOver reads the page structure:
- "Settings, heading level 1"
- Form elements for name, email
- "Subscription, heading level 3"
- Current Plan: badge text
- Feature count text
- Buttons: "Upgrade to Investor Ready," "Manage Subscription"

**Accessibility of the billing section:**
The tier badge uses `<span class="badge badge-watch">`. VoiceOver reads the text content. This is fine — the badge text is semantic (e.g., "Growth").

The "Upgrade to Investor Ready" button is inside a `<form>` with a hidden input. It is keyboard-focusable and has visible text. Good.

### Step 2: Devon checks the price for their 3 companies

The settings page does not show the dollar amount. Devon hears "Growth" as the tier name but not "$199/mo." Devon must navigate to the pricing page or use the Stripe portal to find the actual price.

### Step 3: Devon clicks "Manage Subscription"

This submits a form and redirects to Stripe's billing portal. The Stripe portal is a third-party page.

**Accessibility concern:** Stripe's billing portal is generally accessible (Stripe invests in a11y), but the redirect takes Devon out of Foundry with no announcement. VoiceOver does not announce "you are now on a Stripe page." Devon loses context.

### Step 4: Devon navigates the products list

The products card lists 3 products. Each product row has a name, optional GitHub URL, and a "View" link. The structure uses `<div>` elements with inline styles.

**Accessibility issues:**
1. Products are listed in `<div>` elements, not `<ul>/<li>` elements. Screen readers do not announce "list of 3 items."
2. The "View" link text is generic — VoiceOver reads "View, link" for each product. No association between the product name and the "View" link. Should be "View Acme Corp, link."

**Codebase evidence:** `src/routes/dashboard/settings.ts` lines 99-106 — products are rendered in `<div>` elements with a generic `<a>View</a>` link. No `aria-label` on the link to associate it with the product name.

### Step 5: Devon checks the "+ Add Product" link

The link "Add Product" at the bottom of the products card takes Devon to `/onboarding`. It is a standard `<a>` tag. VoiceOver reads it correctly. Good.

### Step 6: Devon evaluates the Wisdom Network toggle

The wisdom toggle uses a `<label class="toggle">` wrapping a checkbox. The checkbox has no visible label text — the label text is in a sibling `<div>`. The checkbox `title` attribute provides hover text but title is not announced by all screen readers.

**Codebase evidence:** `src/routes/dashboard/settings.ts` lines 124-135 — the toggle checkbox has a `title` attribute but no `aria-label` or associated `<label>` with text.

### Step 7: Devon assesses overall settings page accessibility

Summary:
- Heading structure: H1 "Settings", H3 for cards. No H2. Heading hierarchy is broken.
- Form labels: name/email inputs are inside the `settingsPage()` component (would need to check that function for labels)
- Interactive elements: buttons have text labels (good), links are generic "View" (bad)
- Color-only indicators: tier badge uses `badge-watch` class which likely has color. The text content ("Growth") is the accessible name, not the color. Good.

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | HIGH | **No price displayed on settings page.** Devon hears "Growth" tier but not the cost. Must leave Foundry to find pricing. |
| 2 | HIGH | **Generic "View" links on products list.** VoiceOver reads "View, link" with no product context. Each product's "View" link should have `aria-label="View [product name]"`. |
| 3 | HIGH | **Products not in a list element.** `<div>` elements instead of `<ul>/<li>`. Screen reader users do not know how many products are listed. |
| 4 | MEDIUM | **Wisdom toggle lacks accessible label.** The checkbox uses `title` attribute but no `aria-label`. Some screen readers will not announce its purpose. |
| 5 | MEDIUM | **Heading hierarchy broken.** H1 then H3 (no H2). Screen reader users navigating by heading level will have gaps. |
| 6 | MEDIUM | **Stripe redirect loses context.** "Manage Subscription" sends Devon to Stripe with no announcement of the context change. |

## Cross-Company Awareness Check

Devon has 3 companies on a flat-rate tier. No cross-company billing boundary issues. Each company is listed independently in the products card.

## Verdict: JOURNEY PARTIAL — Billing works via Stripe delegation but settings page has multiple accessibility gaps
