Casey is evaluating Foundry with a single test company on Solo tier. As part of the security review for team adoption, Casey needs to verify: (1) what data export options exist, (2) whether the platform supports GDPR compliance, and (3) what happens to data on cancellation.

**Result:** PASS -- Privacy page is accessible on Solo tier.

### Step 2: Review data sharing consents

Casey reviews the 4 consent toggles: Anonymized Benchmarking, Aggregate Insights, Help Improve Foundry, Opt Out of AI Training.

**Codebase finding:** privacy.ts lines 96-120 define the consent items. Each has a label, description, and "Learn more" expandable detail. Toggles use `onchange="this.closest('form').submit()"` for immediate save. Each consent records `ip_address` and timestamp.

**Positive finding:** The consent UX is well-structured. Each option has clear copy, a "Learn more" expansion, and a last-updated timestamp. The AI training opt-out defaults to explicit preference recording, not assumed consent.

**Result:** PASS -- Consent management is clear and well-documented. Good for Casey's security review.

### Step 3: Review data residency settings

Casey checks region selection, data retention, and agent log retention.

**Codebase finding:** privacy.ts lines 153-183 offer 4 regions (US East, US West, EU West, AP Southeast), 4 retention periods (1 year, 2 years, 5 years, Forever), and 3 log retention periods (30, 90, 365 days).

**Friction:** The "Data residency enforcement coming soon" note (line 219) indicates that region selection is aspirational -- data is not actually stored in the selected region. Casey's security review would flag this as a gap.

**Result:** FRICTION (MEDIUM) -- Data residency selection exists but is not enforced. The UI discloses this with a "coming soon" note, which is honest but a blocker for compliance-sensitive evaluations.

### Step 4: Test data export

Casey clicks "Download JSON" to test the export.

**Codebase finding:** privacy.ts line 375-402 serves the export. The JSON includes `exported_at`, `product_id`, `product_name`, and the data payload from `exportProductData()`.

**Friction:** Export is JSON only. For Casey's security review, the evaluator might need to verify the completeness of the export -- what tables are included, whether agent activity logs are present, whether customer data is included. The export description says "metrics, briefings, decisions, customers, and agent configuration" but without seeing the actual output, completeness is unverifiable.

**Result:** FRICTION (LOW) -- Export works but completeness is unverifiable without documentation of exactly what's included.

### Step 5: Review deletion process

Casey reviews the "Request Account Deletion" section.

**Codebase finding:** privacy.ts line 272-309 shows the deletion section with a confirmation modal. POST `/privacy/delete` calls `scheduleDataDeletion(ctx.productId, 30)` -- 30-day delayed deletion. The modal text says "permanently schedule deletion" and "cannot be undone."

**Friction:** The deletion is "scheduled" with a 30-day delay, but there is no mention of a cancellation window. If Casey wants to present "data deletion is reversible within 30 days" to the CTO, the UI does not confirm this. Also, the deletion is per-product, not per-account -- deleting the product does not delete the founder account.

**Result:** FRICTION (MEDIUM) -- 30-day deletion schedule with no documented cancellation window. Per-product deletion, not per-account.
