## SPECIAL ATTENTION: Data Deletion Executor Verification

**Does the data deletion executor actually process?**

**NO. The deletion executor is dead code. It is never called by any scheduled job.**

### Evidence Chain

1. **Privacy page deletion handler** (`src/routes/dashboard/privacy.ts` line 412-413):
   ```typescript
   const { scheduleDataDeletion } = await import('../../services/privacy/consent.js');
   await scheduleDataDeletion(ctx.productId, 30);
   ```
   This writes a `data_deletion_scheduled` event to `agent_audit_log`. That is all it does.

2. **Scheduled deletion processor** (`src/services/privacy/consent.ts` lines 316-372):
   `processScheduledDeletions()` exists and would find scheduled deletions past their threshold and execute them. But it is **never called from any route, job, or scheduler**.

3. **JOB_REGISTRY** (`src/jobs/index.ts` lines 1796-1867):
   The registry lists 55+ jobs. Neither `processScheduledDeletions` nor `processAccountDeletions` nor `processDataExports` appears. None of the GDPR functions are registered.

4. **GDPR job file** (`src/jobs/gdpr.ts`):
   Contains `processDataExports()` and `processAccountDeletions()`. These are exported but **never imported by the job registry or the index.ts cron scheduler**.

5. **No other caller**: Grepping the entire codebase for `processScheduledDeletions`, `processAccountDeletions`, and `processDataExports` shows zero call sites outside their definition files.

**CONCLUSION: When Robin clicks "Yes, Delete Everything," nothing ever happens.** The deletion is "scheduled" (an audit log entry is written), but no cron job or background process ever picks it up. The data persists indefinitely. The agents continue running. Billing continues.

The deletion flow is theatrical — it performs the ceremony of deletion (modal, confirmation, success message) but executes none of the substance.

## Simulation Transcript

### Step 1: Robin navigates to the deletion flow

Robin goes to `/privacy`. Finds "Delete My Data" at the bottom. Clicks it. Modal appears.

### Step 2: Robin reads the modal carefully

The modal says:
- "This will permanently schedule deletion of all your product data including metrics, briefings, decisions, and agent logs."
- "This cannot be undone."
- Recommends exporting data first.

Robin has already exported data manually (Run 099). Robin clicks "Yes, Delete Everything."

### Step 3: What Robin expects to happen

1. Data deletion scheduled for 30 days from now
2. Stripe subscription cancelled
3. SCP agents stopped
4. GitHub tokens revoked
5. Confirmation email with receipt
6. After 30 days: all data permanently deleted

### Step 4: What actually happens

1. An `agent_audit_log` entry is written with `event_type='data_deletion_scheduled'`
2. Robin is redirected to `/privacy?success=deletion_scheduled`
3. A generic "Settings saved successfully" banner appears

**That is all that happens.** Nothing else changes:
- Stripe subscription continues charging Robin $199/mo
- SCP agents continue running hourly
- New briefings, decisions, and signals continue accumulating
- GitHub token remains active and valid
- No confirmation email is sent
- No grace period UI appears
- The `processScheduledDeletions()` function that would eventually delete the data is never called by any scheduler

### Step 5: Robin waits 30 days

After 30 days, Robin checks back. Nothing has been deleted. The product is still active. The agents are still running. Robin has been charged another $199.

Robin's response: "I clicked 'Delete Everything' a month ago and nothing happened. I'm still being charged. The agents are still running. This is either a bug or a dark pattern."

### Step 6: Robin tries to cancel billing separately

Robin goes to Settings > Manage Subscription > Stripe Portal. Robin cancels the Stripe subscription. This stops future charges but does not delete data, stop agents (if the SCP scheduler does not check billing status), or revoke tokens.

### Step 7: Robin's actual exit path

Robin's only option for a clean exit:
1. Cancel Stripe subscription manually via portal
2. Revoke GitHub token manually in GitHub settings
3. Accept that data persists in Foundry's database indefinitely
4. Accept that anonymized patterns from Robin's product continue influencing other founders
5. Accept that no deletion receipt or confirmation exists

## Cross-Company Awareness Check

Robin previously had 2 products. The first was "removed" (likely via the same broken deletion flow — meaning it too was never actually deleted). Robin's remaining product also has a scheduled-but-never-processed deletion.

**Result:** Both of Robin's products may still have data persisting in Foundry's database despite Robin believing both were deleted.

**Pattern leak:** Decision patterns from both of Robin's products persist in the global `decision_patterns` table and continue influencing other founders' agent recommendations. Even after "deletion," Robin's operational patterns remain in the system with no access controls.

## Technical Root Cause

The architecture has three deletion mechanisms, none of which are wired end-to-end:

| Mechanism | Entry Point | Processor | Registered? |
|-----------|-------------|-----------|-------------|
| Privacy page deletion | `POST /privacy/delete` -> `scheduleDataDeletion()` | `processScheduledDeletions()` | **NO** — not in JOB_REGISTRY |
| GDPR account deletion | None (no UI) | `processAccountDeletions()` | **NO** — not in JOB_REGISTRY |
| GDPR data export | None (no UI) | `processDataExports()` | **NO** — not in JOB_REGISTRY |

The inline privacy export (`GET /privacy/export`) works because it is synchronous. But the three async job-based functions are orphaned.

## Regulatory Exposure

If Foundry processes data for EU residents:
- **GDPR Article 17 (Right to Erasure):** Deletion requests are accepted but never processed. This is a GDPR violation.
- **GDPR Article 20 (Data Portability):** The background export job exists but is not registered. Only the incomplete inline export works.
- **CCPA:** Similar right-to-delete obligations. Same violation.

Robin is told "your data will be deleted" but it is not. This could constitute a deceptive practice under consumer protection law.

## Verdict: JOURNEY CATASTROPHICALLY FAILED — Deletion is completely non-functional. Dead code creates the illusion of data removal while retaining all data, continuing billing, and running agents indefinitely.
