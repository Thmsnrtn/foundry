# Run 006 — Jamie (Two-Product Founder) on Journey 01 (Landing to First SCP)

## Conditions
Fleet size: 0 → 1
Tier: Growth ($199)
Device: iPad, Safari
Network: Home Wi-Fi

## Step-by-Step

1. **Jamie lands on foundry.so** → Sees hero and 12 agent cards. → Jamie skims the agent names: "CTO, Product, UX Lead, CMO... okay, it's like having a team." The "How It Works" section is clear enough for a non-technical user.
2. **Clicks "Give my product a team →"** → Clerk sign-up. Jamie uses email/password (not GitHub OAuth). → Sign-up completes, redirect to `/dashboard` → `/onboarding`.
3. **Onboarding wizard step 1** → Jamie sees "Connect GitHub →" and "I don't have a repo →". → Jamie thinks: "I have repos but my contract devs manage them. I don't have personal access." Clicks "I don't have a repo →".
4. **No-code path at `/onboarding/no-code`** → Form: Product Name, Product URL, Built With (dropdown: Bubble, Webflow, etc.), Sector (dropdown). → Jamie enters: "ScheduleWidget", "https://schedulewidget.com", "Other", "B2B SaaS". Clicks "Continue →".
5. **Product created** → Redirects to `/onboarding/competitors?product_id=xxx`. → Jamie enters 1 competitor. Submits.
6. **Audit page** → Jamie triggers audit. Since there's no GitHub repo, the audit runs on the URL only. → **FRICTION**: The audit pipeline is designed for GitHub repos (8-step analysis: stack detection, config, routes, billing, trust, errors, analytics, deps). A URL-only product gets a degraded audit. Jamie doesn't know this.
7. **Redirects to dashboard** → Signal score appears (lower than it would be with a repo, maybe 45). Prose summary is generic because no code was analyzed. → Jamie reads: "ScheduleWidget is in early stages. Limited data available."
8. **Jamie's reaction** → "This doesn't tell me anything I don't already know. Where's the team of agents they promised?" Jamie looks at the briefing card — it's thin because agents haven't had a cycle yet.

## Cross-Company Awareness
Did the user get confused about which company they were acting on? **NO** — Single company. No confusion possible.

## Friction Events
- FRICTION-0012: HIGH — The no-code onboarding path produces a significantly degraded experience. The 8-step audit is built for GitHub repos. A URL-only product gets minimal analysis, resulting in a generic first briefing. Jamie's abandonment trigger #3: "Cannot figure out which product is healthier at a glance within 5 seconds."
- FRICTION-0013: MEDIUM — No expectation-setting about what the URL-only audit can and cannot do. Jamie expects the same depth as the marketing page promises.
- FRICTION-0014: LOW — SCP provisioning fires for the no-code product, but agents like Atlas (CTO) and Crucible (QA) have almost nothing to work with since there's no codebase to analyze.

## Verdict: SUCCESS (barely) — onboarding completed but first impression is underwhelming
## Would Recommend: Not Yet — "The agents don't seem to know anything about my product yet."
