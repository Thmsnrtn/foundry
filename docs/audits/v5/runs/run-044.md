## Step-by-Step Transcript

1. Riley logs in. Portfolio view (15 companies). Riley needs a complete data export for regulatory compliance.
2. Riley navigates to Privacy (`/privacy`) for the first product.
3. Riley clicks "Download JSON." Export for Company #1 downloads (2-4 seconds).
4. Riley needs to repeat this for all 15 companies. Opens a mental timer.
5. Switch to Company #2 (portfolio -> click -> privacy -> download). ~20 seconds per round-trip.
6. Switch to Company #3. Repeat. This is painfully slow for Riley (who types faster than most people read).
7. By Company #5, Riley estimates total time: 15 companies x 20 seconds = 5 minutes of mechanical clicking. Plus 15 partial JSON files to manage.
8. **Riley stops.** This is unacceptable. Checks for an API-based approach.
9. Riley opens browser DevTools. Checks the export URL: `GET /privacy/export`. No API key auth — requires browser session cookie.
10. Riley considers scripting: `curl` with the session cookie, looping over product IDs. But product IDs are not easily accessible — they are internal nanoid strings, not in any API listing.
11. Riley checks `/products` JSON API endpoint. `productRoutes.get('/products')` exists and returns `{ products: result.rows }`. Uses session auth.
12. Riley scripts in the browser console: fetch product list, iterate, download each export. This works but is a hack — not a designed workflow.
13. **Workaround**: Riley writes a browser console script:
    ```javascript
    const products = await (await fetch('/products')).json();
    for (const p of products.products) {
      // would need to switch product cookie and fetch export for each
    }
    ```
14. But the export endpoint uses the cookie-based product context, not a product ID in the URL. Riley would need to POST to `/switch-product` between each export, which requires CSRF tokens.
15. Riley gives up on automation. Manually exports 15 companies over 5 minutes.
16. 15 JSON files downloaded. All named `foundry-export-2026-04-16.json` with browser-appended numbers.
17. Each file is a partial export (5 of 15+ tables). For a regulatory compliance export, this is insufficient.
18. **Total data exported**: ~750KB across 15 files. **Missing data** (stressors, audit scores, SCP briefings, competitive signals, etc.) would likely be 3-5x larger.
19. Riley would need to explain to a regulator that Foundry only exports 33% of the data categories in the self-service flow.

## Cross-Company Awareness Check

- **Per-product export**: Each correctly scoped. No cross-contamination.
- **Product switching**: Works via portfolio clicks. Correct product selected for each export.
- **Scaling**: O(n) export at F15 is unacceptable. 5 minutes of mechanical clicking for partial data.

## Friction Events

| # | Severity | Category | Description |
|---|----------|----------|-------------|
| F044-1 | CRITICAL | Scalability | Exporting 15 companies requires 15 individual round-trips (~5 minutes). No batch export, no API-driven export, no automation path. |
| F044-2 | HIGH | Incomplete Export | Self-service export covers 5 of 15+ tables. Regulatory compliance requires comprehensive export. |
| F044-3 | HIGH | API Gap | Export endpoint uses cookie-based product context instead of URL parameter. Cannot be automated or scripted easily. |
| F044-4 | MEDIUM | Filename Collision | 15 files with identical filenames. |
| F044-5 | MEDIUM | No Queuing | All exports synchronous. At 15 companies with 3 months of data, a queued batch job would be more appropriate. |

## Verdict

**FAILED**

Compliance export at F15 is a manual, time-consuming process that produces incomplete data. No batch export, no API, no queuing. Riley cannot satisfy regulatory requirements with the current tooling.

## Recommendation

1. Add `/privacy/export-all` endpoint that creates a ZIP with per-company directories.
2. For large exports, queue the job and deliver via email notification with a time-limited download link.
3. Add a URL-parameter-based export endpoint: `GET /privacy/export/:productId` to enable scripting.
4. Wire to the comprehensive GDPR export job (15+ tables) instead of the partial `exportProductData` function.
5. Include a manifest and schema in the export archive.
