# Run 084 — Taylor (P07) x Compliance Export (J09)

**Persona:** Taylor — returning user after 6-week absence, Growth tier, 1 company
**Journey:** Compliance export (GDPR-style)
**Severity Baseline:** Taylor wants to understand what agents did during absence; export might help.

---

## Simulation Transcript

### Step 1: Taylor considers using export to catch up

Taylor's primary need is a "what happened while I was gone" summary. The compliance export might serve as a data dump that Taylor could analyze externally.

Taylor navigates to `/privacy` and clicks "Download JSON."

### Step 2: Taylor examines the export

The export contains:
- `metrics` — all metric snapshots (useful for trend analysis)
- `briefings` — SCP briefings (most useful — contains headlines and health scores by date)
- `decisions` — all decisions with status and dates (includes the 23 pending ones)
- `customers` — customer records
- `agent_config` — agent configuration

**Partial success for Taylor's use case:** The briefings data, sorted by date, gives Taylor a daily headline summary of what the agents concluded. This is not a "catch-up digest" but is raw material for one.

### Step 3: Taylor notes what's missing from the export

Same gaps as Run 079:
- No agent activity logs (the actual actions agents took)
- No signal history (the score trajectory over time)
- No stressor history (what risks were flagged and resolved)

For Taylor's "what happened" use case, stressor history would be the most valuable missing data — it would show "week 2: churn stressor fired, week 4: it resolved."

### Step 4: Taylor checks if 42 days of briefings are in the export

The `scp_briefings` query has no date range limit (`ORDER BY briefing_date DESC`). If the SCP generated daily briefings for 42 days, all 42 should appear. This is good — Taylor gets 6 weeks of daily briefing headlines.

However, the briefing records exported only include: `id, product_id, briefing_date, headline, health_score, signal_score, risk_state, created_at`. The full briefing body (detailed analysis, per-agent summaries, risk decomposition) is not included — only the headline.

**Codebase evidence:** `src/services/privacy/consent.ts` lines 254-257 — explicit column selection excludes the full briefing content.

### Step 5: Taylor wants to filter export by date range

No date range filter available on export. The entire dataset downloads. For a long-running product, this could be hundreds of metric snapshots and briefings. Taylor must filter externally.

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | HIGH | **Briefing headlines exported but not full briefing content.** The most useful data for Taylor (daily briefing body) is excluded from the export. Only headline, score, and risk state are included. |
| 2 | HIGH | **Agent activity logs not exported** (same as Run 079). Taylor cannot reconstruct what agents actually did. |
| 3 | HIGH | **Stressor history not exported.** The rise and fall of risk factors during absence is invisible in the export. |
| 4 | MEDIUM | **No date range filter on export.** Taylor must download all data and filter externally. |
| 5 | HIGH | **No CSV option** (same as Run 079). Taylor might want to open the data in a spreadsheet for analysis. |
| 6 | MEDIUM | **Export serves compliance, not catch-up.** The export is designed for data portability, not for "help me understand what happened." Taylor needs a different tool that does not exist. |
