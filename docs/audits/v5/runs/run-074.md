## Preconditions

Jamie has 3 companies on Growth tier. Wants to scale toward 15. As a serial founder, Jamie is testing whether Foundry's fleet management scales with the portfolio.

## Transcript

### Step 1: Tier assessment for scaling

Jamie wants to add a 4th, 5th, etc. company. Growth tier ($199) supports multi-company, but is there a limit before needing to upgrade to Investor-Ready ($399)?

**Codebase finding:** `src/middleware/tier-gate.ts` handles feature access based on tier. The tier definitions from the orientation: Solo (single company), Growth (multi-company), Investor-Ready (full fleet + portfolio). The exact company count limits per tier are not documented in the orientation. If Growth has an undocumented cap (e.g., 5 companies), Jamie would need to upgrade.

**Friction:** Growth tier company limit is ambiguous. The UI should clearly state "Growth supports up to N companies" on the pricing or settings page. If the limit exists, the tier-gate error message should include the limit and an upgrade CTA.

**Result:** FRICTION (MEDIUM) -- Growth tier company limit not clearly documented. Upgrade path unclear.

### Step 2: Repeat add-company flow

Jamie adds company #4 using the products management flow.

**Codebase finding:** Same undiscoverable add-company pattern as F-053-A. Jamie, being an experienced user, likely knows where to find it by now.

**Result:** FRICTION (LOW) -- Repeat users learn the path, but initial discoverability was poor.

### Step 3: Fleet view at 4 companies

Jamie has 4 companies and examines the fleet management experience.

**Codebase finding:** The product switcher `<select>` now has 4 items. No fleet view, no sorting, no comparative dashboard. Each company is accessed individually.

**Friction:** At 4 companies, the single-company-at-a-time model starts to show strain. Jamie must mentally track the state of 4 products with no fleet summary. The J03 success criteria (sort by health, MRR, risk state) remain unmet.

**Result:** FRICTION (HIGH) -- No fleet view. Single-company model strains at 4+ companies.

### Step 4: Command palette for navigation

Jamie uses Cmd+K to open the command palette for faster navigation.

**Codebase finding:** The command palette (layout.ts line 124-152) has 27 route entries. These are page-level navigation items, not product-specific actions. There is no "Switch to [Company Name]" entry. Searching for a company name yields no results.

**Friction:** Command palette does not support product switching. A power user like Jamie expects "Cmd+K > type company name > switch" workflow. The palette only navigates within the current company.

**Result:** FRICTION (HIGH) -- Command palette lacks product switching. Power users cannot switch companies via keyboard command.

### Step 5: Assess scaling trajectory

Jamie projects: At this rate, reaching 15 companies means 12 more add-company cycles, each requiring 3-5 minutes. The fleet management experience does not improve with scale -- it degrades. The product switcher dropdown becomes increasingly long with no search. The lack of fleet view means triage time grows linearly.

**Result:** Assessment: Foundry does not currently scale as a fleet management tool. It is a single-company tool with a product switcher. The "multi-company control plane" positioning is aspirational.

### Step 6: Cross-company boundary check

Jamie switches rapidly between 4 companies.

**Cross-company awareness check:** PASS. The cookie-based switching correctly isolates data at 4 companies. No residual data or cross-contamination.

**Result:** PASS -- Boundary maintained at F4.
