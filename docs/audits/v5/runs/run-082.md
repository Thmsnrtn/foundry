# Run 082 — Taylor (P07) x Company Retirement (J07)

**Persona:** Taylor — returning user after 6-week absence, Growth tier, 1 company
**Journey:** Company retirement / archival
**Severity Baseline:** Taylor returned to chaos; retirement is not the goal but understanding what agents did is.

---

## Precondition Check

Taylor has 1 company. Journey 07 requires 2+. This is the "last active company" edge case.

Taylor's unique angle: Taylor is not trying to retire a company right now. But after 6 weeks of unsupervised agent activity, Taylor might discover that agents caused harm and want to pause/retire/wind-down agent activity rather than continue operating blindly.

---

## Simulation Transcript

### Step 1: Taylor wants to pause agents, not retire the company

After returning and seeing 23 pending decisions, Taylor's first instinct might be: "Stop everything, let me catch up, then re-enable."

**No agent pause/resume capability exists in the UI.** The SCP provisioner has `deprovisionSCP()` which archives (permanently), but there is no "pause all agents temporarily" button. The schema supports `scp_status='paused'` and `agent_instances.status='paused'`, but no route exposes this.

### Step 2: Taylor looks for agent history during absence

Taylor goes to `/agents` to see the agent roster. The agents page shows current state (health scores, lifecycle stage, last run time) but no historical view of "what did each agent do over the last 42 days."

Taylor goes to `/audit-log`. The audit log shows timestamped entries with actor type, action, resource, and details. This is the closest thing to an activity history. It is filterable by actor type and date.

**Partial success:** Taylor can filter to `actor_type=agent` and `since=2026-03-05` (42 days ago) to see all agent actions during absence. But the log is capped at 100 entries, and there is no pagination.

**Codebase evidence:** `src/routes/dashboard/audit-log.ts` line 77 — `LIMIT 100` with no pagination.

### Step 3: Taylor finds the retirement flow is missing

Same findings as Run 077 — no "Retire Company" button anywhere. Only deletion via privacy page.

### Step 4: Taylor considers the edge case of retiring their only company

If Taylor decided to retire their only company, it would leave zero active products. The dashboard redirect logic (`src/routes/dashboard/index.ts` lines 128-129) sends founders with zero products to `/onboarding`. So Taylor would enter a "no products, re-onboard" state — which makes sense but is jarring for a returning user who might want a graceful archive-and-exit.

---

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | HIGH | **No agent pause/resume in UI.** Taylor cannot temporarily halt agent activity while catching up. The schema supports paused state but no route exposes it. |
| 2 | HIGH | **Audit log capped at 100 entries, no pagination.** For 42 days of 12 agents running hourly, Taylor may have 12,000+ log entries. Only the latest 100 are visible. |
| 3 | CRITICAL | **No retirement flow** (same as Run 077). |
| 4 | MEDIUM | **Retiring the only company redirects to onboarding.** No graceful "your company is archived, here's the read-only view" — just back to "add your first product." |
| 5 | HIGH | **No absence-aware agent activity summary.** The audit log has raw entries but no summary like "Atlas ran 42 times, made 7 recommendations, 3 were auto-approved." Taylor must manually count and categorize. |

## Cross-Company Awareness Check

Not applicable — single company.

## Verdict: JOURNEY FAILED — No retirement flow, no agent pause, limited activity history
