# Run 099 — Robin (P10) x Compliance Export (J09)

**Persona:** Robin — frustrated user about to churn, Growth tier, 1 company
**Journey:** Compliance export (GDPR-style)
**Severity Baseline:** Robin has "already exported most data manually." This implies Robin tried the export and found it insufficient.

---

## Simulation Transcript

### Step 1: Robin's prior export experience

Robin's persona says they "already exported most data manually." This means Robin previously used the `/privacy/export` JSON download and found it incomplete — then resorted to manual data extraction (screenshots, copy-paste from dashboard pages, or other workarounds).

This is consistent with the export incompleteness findings from Runs 079, 084, 089, and 094.

### Step 2: Robin returns to export for final pre-exit data grab

Robin goes to `/privacy` and clicks "Download JSON" one more time to get the latest state before deletion.

### Step 3: Robin evaluates what "manually exported" means

Since the automated export is missing:
- Agent activity logs
- Signal history
- Stressor history
- Audit scores and remediation records
- Decision vote history

Robin would have had to:
- Visit `/audit-log` and manually copy entries (limited to 100, no pagination)
- Visit `/agents` and copy health scores per agent
- Visit `/decisions` and copy each decision's details individually
- Take screenshots of charts and visualizations

For an 18-month user with 12 agents running hourly, this is thousands of data points that cannot be extracted via the export tool.

### Step 4: Robin checks for the data they care about most

Robin's primary concern is post-departure: "whether agent-generated PRs will remain in the GitHub repo after departure." This is not about Foundry's export — it is about what happens to artifacts the agents created in Robin's GitHub repo.

**Foundry's export does not address this.** The export covers Foundry's internal data, not what was pushed to GitHub. Robin's concern is about:
1. Agent-generated branches still existing in the repo
2. Agent-generated PRs still open in GitHub
3. Agent-generated commits still in the git history

None of this is in Foundry's control after the PR is merged. The answer is: yes, agent-generated artifacts remain in GitHub because they are GitHub artifacts, not Foundry artifacts. But Foundry does not explain this anywhere.

### Step 5: Robin checks for data the agents hold about their codebase

Robin is concerned about proprietary data retention. The agents analyzed Robin's GitHub codebase (code structure, dependencies, configuration files). This analysis data is stored in Foundry's database (audit_scores, agent prompts, analysis results).

**The export does not include agent analysis data.** The raw analysis that the agents performed on Robin's codebase — which includes information about Robin's proprietary code — is not exportable and not explicitly addressed in the deletion flow.

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | CRITICAL | **Export is too incomplete to support pre-churn data preservation.** Robin "already exported most data manually" because the automated export fails to capture the most valuable data. |
| 2 | HIGH | **No information about GitHub artifact persistence.** Robin's concern about agent-generated PRs/branches/commits remaining in GitHub is not addressed anywhere in the export or deletion flow. |
| 3 | HIGH | **Agent analysis of proprietary code is not exportable.** The agents analyzed Robin's codebase. That analysis data is retained but not included in the export. Robin cannot verify what Foundry knows about their code. |
| 4 | HIGH | **Audit log has no pagination.** For an 18-month user, the audit log's 100-entry limit means only the most recent entries are visible. Robin cannot manually export historical agent activity. |
| 5 | MEDIUM | **Export does not address the "what do you keep after I leave" question.** Robin wants to know what data Foundry retains post-deletion. The export shows what Robin can take, but not what Foundry keeps (anonymized patterns, aggregate data). |
| 6 | MEDIUM | **No export manifest or data inventory.** Robin cannot compare "what I exported" vs. "what Foundry holds" to identify the gap. |

## Cross-Company Awareness Check

Robin previously had 2 companies. The removed company's data may have been exported before removal (if Robin thought to do so) or lost. The current export covers only the remaining company. No cross-company export. No "export everything including deleted products" option.

**Boundary concern:** Patterns from Robin's removed product may persist in the global `decision_patterns` pool. Robin cannot export or verify these remnant contributions.

## Verdict: JOURNEY FAILED — Export is fundamentally inadequate for pre-churn data preservation. Robin resorted to manual extraction and still cannot capture everything.
