# Run 010 — Jamie (Two-Product Founder) on Journey 05 (Remediation PR Review)

## Conditions
Fleet size: 2
Tier: Growth ($199)
Device: iPad, Safari
Network: Home Wi-Fi

## Step-by-Step

1. **Jamie logs in** → Dashboard for ScheduleWidget. Briefing card mentions Atlas generated a remediation PR for a missing CSRF token on a webhook endpoint.
2. **Jamie clicks the notification** → Navigates to the briefing detail. Sees "Atlas: opened remediation PR — CSRF protection for /api/webhooks." → Jamie thinks: "What's CSRF? What's a webhook endpoint?"
3. **Jamie navigates to Remediation** → Goes to `/products/{id}/remediation`. Growth tier includes remediation. Page loads showing: remediation summary card (1 PR open, 0 merged, 0 dismissed) and a PR list.
4. **Jamie clicks the PR** → PR detail shows: what was found (missing CSRF token validation), why it matters (potential cross-site request forgery), what the fix does (adds token validation middleware), and which audit dimension it addresses (D5: Operational Readiness). → **FRICTION**: Jamie doesn't understand the technical explanation. "CSRF token validation middleware" means nothing to a non-technical founder.
5. **Jamie sees "View on GitHub" link** → Clicks through to the actual GitHub PR. Jamie doesn't have GitHub access (contract devs manage the repo). → Dead end. Jamie can't review the code diff.
6. **Jamie returns to Foundry** → The PR detail page has an approve/dismiss flow. Jamie hesitates. "I don't understand what this changes. What if it breaks something?" → No "explain like I'm not a developer" option.
7. **Jamie defers the decision** → Leaves the PR open. Plans to ask the contract dev to review it.
8. **Jamie switches to InsightPulse** → Uses product switcher. Navigates to Remediation for InsightPulse. 0 PRs. → "Okay, nothing here."

## Cross-Company Awareness
Did the user get confused about which company they were acting on? **NO** — Jamie checked both products separately. The remediation view clearly shows the product name.

## Friction Events
- FRICTION-0026: HIGH — Remediation PR descriptions use developer terminology (CSRF, middleware, webhook endpoint) with no plain-language explanation. Jamie's abandonment trigger #2: "Terminology assumes engineering fluency without explanation."
- FRICTION-0027: MEDIUM — The "View on GitHub" link assumes the founder has GitHub access. Non-technical founders who use contract dev teams often don't. No fallback explanation of the code changes.
- FRICTION-0028: MEDIUM — No "explain this to me" or "what does this mean for my business" option on the remediation detail. The PR description is code-focused, not business-focused.
- FRICTION-0029: LOW — No cross-company remediation queue. Jamie must check each product's remediation page separately.

## Verdict: ABANDONED — Jamie couldn't understand or act on the remediation
## Would Recommend: No — "When the agent says 'remediation PR merged,' I need to know what that means for my revenue."
