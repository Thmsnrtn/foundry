# Run 076 — Jordan (P06) x Cross-Company Intelligence (J06)

**Persona:** Jordan — compliance-minded fintech founder, Growth tier, 1 company
**Journey:** Cross-company intelligence investigation
**Severity Baseline:** Jordan has regulatory obligations; audit trail completeness is load-bearing.

---

## Precondition Check

Jordan has 1 company on the Growth tier ($199/mo). Journey 06 requires 3+ companies with active SCP and at least 2 weeks of data.

**BLOCKER: Fleet size = 1. Journey cannot begin.**

The Growth tier does not gate multi-product, but the Investor-Ready tier ($399) is the only one marketing fleet features. Jordan would need to:
1. Upgrade to Investor-Ready
2. Add at least 2 more companies
3. Wait 2 weeks for SCP data accumulation

There is no upsell prompt or messaging in the dashboard that tells a Growth-tier founder "you could see cross-company patterns if you added more products." The feature is simply invisible.

---

## Simulation Transcript

### Step 1: Jordan navigates to dashboard

Jordan sees the Signal score, stressor report, and CEO briefing for their single fintech product. No fleet intelligence link exists in the sidebar navigation. No "cross-company insights" card appears.

**Codebase evidence:** `src/routes/dashboard/index.ts` lines 132-136 — if only one product exists and a cookie is set, it goes straight to single-product dashboard. There is no cross-company intelligence route in `src/routes/dashboard/` at all.

### Step 2: Jordan searches for cross-company features

Jordan uses the command palette (Cmd+K). Typing "cross-company" or "fleet" yields no results. The command palette searches route labels and static action names — there is no entry for fleet intelligence.

### Step 3: Jordan checks the portfolio route

Jordan navigates to `/portfolio`. This shows a basic overview if they have multiple products but is gated to the investor layer (portfolios table, `pfk_*` API keys). For a single-product Growth-tier founder, this either redirects back to dashboard or shows an empty state.

**Codebase evidence:** `src/services/portfolio/manager.ts` — the portfolio system is designed for investor/VC entities, not for founder-level cross-company intelligence. It aggregates metrics across portfolio memberships but does not extract cross-company patterns or correlations.

### Step 4: Jordan gives up

No cross-company intelligence feature exists in the codebase. The `decision_patterns` table exists for cross-product wisdom but has no access controls (orientation doc problem #17) and no UI for pattern investigation.

## Cross-Company Awareness Check

**CRITICAL boundary issue:** The `decision_patterns` table (`src/services/decisions/patterns.ts`) stores patterns globally with no `owner_id` scope. Jordan's fintech compliance patterns could leak into recommendations for an unrelated product. No consent check. No isolation.

## Verdict: JOURNEY BLOCKED — Feature does not exist
