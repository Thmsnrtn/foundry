# Run 027 — Alex x J07 (Company Retirement)

## Conditions

| Axis | Value |
|------|-------|
| Persona | Alex (Solo founder, pre-revenue, 8/10 technical) |
| Journey | J07 — Company Retirement / Archival |
| Fleet size | F1 (1 company) |
| Network | NET-AVG (10 Mbps, 80ms) |
| Screen | SCR-LAP (1440x900) |
| A11Y | A11Y-OFF |
| Account | ACCT-EST (2+ weeks SCP data) |
| Tier | TIER-SOLO ($79) |
| Error | ERR-NONE |

## Precondition Check

Alex has 1 company. Retiring it would leave 0 companies — an edge case. Journey J07 requires 2+ companies to retire one while keeping the fleet. With F1 this is the "last active company" edge case.

## Step-by-Step Transcript

1. Alex logs in. Dashboard loads with single-product Signal view.
2. Alex navigates to Settings (`/settings`).
3. Settings page renders. Alex scans for a "Retire Company" or "Archive" option.
4. **No retire/archive option exists.** The Products section in Settings shows the product name, a "View" link, and an "+ Add Product" button. No retire, deactivate, or archive action.
5. Alex tries the Privacy page (`/privacy`). Section 3 shows "Your Data" with "Export All Data" and "Request Account Deletion."
6. **"Request Account Deletion" deletes the PRODUCT, not the account.** The button says "Delete My Data" and the modal says "permanently schedule deletion of all your product data." This is product deletion, not retirement.
7. Alex reads the modal: "This will permanently schedule deletion of all your product data including metrics, briefings, decisions, and agent logs. This cannot be undone."
8. **No mention of what happens to billing.** The deletion modal does not say whether the subscription is cancelled.
9. **No retirement option exists.** The only path is full deletion. No "pause," "archive," or "retire" state.
10. Alex considers: if they delete the product data, is the founder account still active? Can they add a new product later? The UI does not explain.
11. The `scheduleDataDeletion` function writes an audit log entry and sets a 30-day timer. The product status will eventually become `deleted`. But there is no intermediate "archived" state.
12. Alex decides not to proceed — the deletion is too aggressive for what they want (pausing monitoring while preserving data).

## Cross-Company Awareness Check

- **Single company**: No cross-company confusion possible.
- **Deletion scope**: The `/privacy/delete` endpoint acts on `ctx.productId` (the currently selected product). If Alex had multiple products, the deletion would only affect the active product — but the UI says "Delete My Data" (possessive, ambiguous scope).
- **CRITICAL**: The delete action operates on whichever product is selected via the cookie-based switcher. If the wrong product were selected, the user could delete the wrong company's data without realizing it. The modal does not name the product being deleted.

## Friction Events

| # | Severity | Category | Description |
|---|----------|----------|-------------|
| F027-1 | HIGH | Missing Feature | No company retirement/archive option exists. Only full data deletion is available. |
| F027-2 | CRITICAL | Boundary Confusion | Delete modal does not name which product is being deleted. In a multi-product scenario, the user could delete the wrong company's data. The action targets whatever product is in the `foundry_product` cookie. |
| F027-3 | HIGH | Missing Information | Delete modal does not explain billing impact — will the subscription be cancelled? Downgraded? |
| F027-4 | MEDIUM | Irreversibility | No reversible retirement state. Deletion is scheduled with a 30-day window, but there is no UI to cancel a pending deletion. |

## Verdict

**FAILED**

The journey cannot be completed because company retirement does not exist as a feature. The only alternative (full deletion) is irreversible, does not explain billing consequences, and critically, does not identify which product is being deleted.

## Recommendation

1. Add a "Retire Company" action in product settings that stops SCP agents, moves the product to an archived state, and adjusts billing.
2. The delete confirmation modal MUST name the product being deleted (e.g., "You are about to delete all data for **PropertyAccounting Pro**").
3. Add a way to cancel a pending deletion during the 30-day grace period.
4. Explain billing impact in the deletion/retirement flow.
