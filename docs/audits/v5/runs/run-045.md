## Conditions

| Axis | Value |
|------|-------|
| Persona | Riley (Growth-mode operator, 15 companies, 9/10 technical) |
| Journey | J10 — Full Organization Deletion (Churn Path) |
| Fleet size | F15 (15 companies) |
| Network | NET-FAST |
| Screen | SCR-DESK (1920x1080) |
| A11Y | A11Y-OFF |
| Account | ACCT-AGED (3+ months data) |
| Tier | TIER-INV ($399, Investor-Ready) |
| Error | ERR-NONE |

## Step-by-Step Transcript

1. Riley logs in. Has decided to leave Foundry. 15 companies to delete.
2. Riley immediately checks for an "Account Deletion" or "Close Account" option in Settings.
3. Settings page: No account deletion. Only product-level delete in Privacy.
4. Riley navigates to Privacy. Sees "Delete My Data" — per-product.
5. Riley calculates: 15 companies x (portfolio click + Privacy navigate + delete + confirm) = ~10 minutes of mechanical clicking. Plus a separate Stripe cancellation.
6. **Riley's threshold**: "If I can't do this in under 5 minutes, the tool is costing me time." (From persona profile.)
7. Riley starts the deletion sequence. Company #1: Delete. Company #2: Delete.
8. By Company #4, Riley notices something: each time they return to the portfolio, all 15 companies still show. No visual feedback that 3 are now pending deletion.
9. Riley continues. Company #5, #6, #7...
10. At Company #8, Riley accidentally clicks "Delete My Data" on what they think is Company #8 but is actually Company #9 (the portfolio is sorted by Signal score, and the order may have shifted due to a re-computation between page loads).
11. **CRITICAL**: The delete modal does not name the product. Riley may have just deleted the wrong company. But there is no way to know — the confirmation modal says "all your product data" without identifying which product.
12. Riley checks the header product switcher — it shows the correct company. But the momentary doubt breaks trust.
13. Riley continues through Company #15. Total time: ~12 minutes.
14. Riley navigates to Settings -> Manage Subscription -> Stripe portal -> Cancel subscription. Returns. +2 minutes.
15. **Total deletion time: ~14 minutes.** For what should be a single "Close Account" button.
16. **Post-deletion state**: 15 products scheduled for deletion (30-day grace period). Stripe cancelled. But:
    - Founder account persists.
    - 15 GitHub tokens orphaned (not revoked at API level).
    - 180 SCP agent instances still scheduled (12 per company) — they will fail on each hourly run until data is actually deleted.
    - No confirmation email sent.
    - No deletion receipt.
17. For 30 days, the SCP scheduler will attempt to run 180 agents hourly against products pending deletion. These will consume compute resources and potentially generate errors in logs.

## Cross-Company Awareness Check

- **CRITICAL**: Delete modal does not name the product. At F15 with 15 rapid deletions, the risk of deleting the wrong company is HIGH.
- **Portfolio order**: Signal-score sorting means the order can change between page loads if a Signal is recomputed. This makes sequential deletion error-prone.
- **No batch deletion**: Each company requires individual confirmation.

## Friction Events

| # | Severity | Category | Description |
|---|----------|----------|-------------|
| F045-1 | CRITICAL | Scalability | Full org deletion at F15 requires 15 individual deletion cycles + Stripe cancellation. Takes ~14 minutes. No batch/account-level delete. |
| F045-2 | CRITICAL | Boundary Confusion | Delete modal does not name the product being deleted. At 15 companies, user can easily delete the wrong company, especially as portfolio sort order may shift between loads. |
| F045-3 | HIGH | Resource Waste | 180 SCP agent instances continue running against pending-deletion products for 30 days until data is hard-deleted. |
| F045-4 | HIGH | Security | 15 GitHub tokens not revoked at API level. All remain valid at GitHub indefinitely. |
| F045-5 | HIGH | No Confirmation | No email, no receipt, no proof of deletion for any of the 15 companies. |
| F045-6 | MEDIUM | Account Persistence | Founder account (PII) persists after all products deleted. GDPR Article 17 violation. |

## Verdict

**FAILED**

Full organization deletion at F15 is a 14-minute manual ordeal with high risk of accidentally deleting the wrong company. The journey requires a "Close Account" button that does not exist. No confirmation, no receipts, and significant resource waste during the 30-day grace period.

## Recommendation

1. "Close Account" button in Settings that: confirms with account email re-entry, cancels Stripe, stops all SCP agents, revokes all GitHub tokens, schedules all products for deletion, sends confirmation email, enters 30-day grace period, then hard-deletes everything including the founders table row.
2. The delete modal MUST display the product name in bold.
3. Add a "Delete All" option for portfolio operators who want to exit entirely.
4. Immediately stop SCP scheduling for pending-deletion products (add a `deletion_pending` flag to the product that the scheduler checks).
