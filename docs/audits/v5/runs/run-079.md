# Run 079 — Jordan (P06) x Compliance Export (J09)

**Persona:** Jordan — compliance-minded fintech founder, Growth tier, 1 company
**Journey:** Compliance export (GDPR-style)
**Severity Baseline:** This is Jordan's core concern. Auditor demanding exportable evidence of agent activity.

---

## Simulation Transcript

### Step 1: Jordan navigates to Privacy & Data

Jordan goes to `/privacy`. The page has three sections:
1. Data Sharing & Consent (4 toggles with timestamps)
2. Data Residency (region, retention period, agent log retention)
3. Your Data (Export All Data button + Delete My Data button)

Good: the page exists and is self-service. Jordan does not need to email support.

### Step 2: Jordan clicks "Download JSON"

The "Download JSON" link points to `/privacy/export`. This triggers a synchronous JSON export.

**Codebase evidence:** `src/routes/dashboard/privacy.ts` lines 375-402 — the export handler calls `exportProductData(productId, 'json')` and returns a JSON file download.

### Step 3: Jordan examines export contents

The `exportProductData` function exports:
- `metrics` — metric_snapshots table
- `briefings` — scp_briefings (id, date, headline, health_score, signal_score, risk_state)
- `decisions` — decisions (id, title, description, status, category)
- `customers` — customers table (catches errors silently)
- `agent_config` — agent_configs table (catches errors silently)

**CRITICAL GAP: The export does NOT include:**
- **Agent activity logs** (`agent_audit_log` table) — the core compliance artifact Jordan needs
- **Agent action history** — what each agent actually did and when
- **Signal timeline** — the signal_history records
- **Stressor history** — stressor_history table
- **Remediation PRs** — audit remediation records
- **Decision vote history** — if team mode was used
- **Consent records** — privacy_consents table (ironic: the consent data itself is not exported)
- **Gate events** — gate_events table showing autonomy gate decisions

The GDPR job (`src/jobs/gdpr.ts`) exports a much more comprehensive set (15+ tables), but that is a background job for `data_export_requests` — a completely separate code path that the privacy page does not use.

### Step 4: Jordan checks export format and schema

The export wraps the data in `{ exported_at, product_id, product_name, ...data }`. No schema documentation is included in the export. No manifest listing what is included vs. excluded.

**Codebase evidence:** `src/routes/dashboard/privacy.ts` lines 388-397 — plain JSON.stringify with no schema or manifest.

### Step 5: Jordan checks for CSV option

Journey 09 specifies "Choose format: JSON or CSV." Only JSON is available. The `exportProductData` function accepts a `_format` parameter but ignores it — it always returns JSON-shaped data.

**Codebase evidence:** `src/services/privacy/consent.ts` line 239 — the parameter is `_format: 'json' | 'csv'` (underscore prefix = unused).

### Step 6: Jordan checks for scope selection

Journey 09 specifies "Select scope: all companies, specific companies, or specific data categories." The current export:
- Exports only the currently-selected product (no multi-company export)
- No category selection (all-or-nothing within the limited set)
- No company selection UI for multi-product founders

### Step 7: Jordan checks for notification when export is ready

The current export is synchronous — the JSON downloads immediately. For small datasets this works. For large datasets (months of SCP data across 15 companies), this would timeout. There is no background job queue + notification pattern for the inline export.

The GDPR background job (`processDataExports`) does have a queue pattern, but the privacy page does not use it.

### Step 8: Jordan tries to satisfy auditor requirements

Jordan's auditor needs:
1. Complete agent activity log for 90 days -- **NOT IN EXPORT**
2. Timestamps and actor IDs on every action -- **NOT IN EXPORT** (agent_audit_log has these but is excluded)
3. Before/after state on agent changes -- **NOT TRACKED ANYWHERE**
4. Machine-readable format -- **JSON exists but is incomplete**
5. Rollback path documentation -- **NOT TRACKED**

---

## Findings

| # | Severity | Finding |
|---|----------|---------|
| 1 | CRITICAL | **Export omits agent activity logs.** The `agent_audit_log` table (the primary compliance artifact) is not included in the privacy export. The export has metrics, briefings, and decisions but not the actual agent action log. |
| 2 | CRITICAL | **Two separate export paths exist and are inconsistent.** The inline `/privacy/export` exports 5 tables. The GDPR job `processDataExports` exports 15+ tables. They are completely disconnected. Jordan uses the UI path and gets an incomplete export. |
| 3 | HIGH | **No CSV format.** The `_format` parameter is accepted but ignored. Only JSON is returned regardless of input. |
| 4 | HIGH | **No export manifest or schema.** The export is raw JSON with no documentation of what is included, what is excluded, or the schema of each table. |
| 5 | HIGH | **No scope selection.** Single-product export only, no multi-company export, no category filtering. |
| 6 | MEDIUM | **No background job for large exports.** The inline export is synchronous. For accounts with months of data across multiple products, this will timeout. The background GDPR job exists but is not wired to the UI. |
| 7 | HIGH | **Before/after state not tracked.** Agent actions do not record what the state was before and after the action. Even the `agent_audit_log` entries lack diff/delta information. |
| 8 | MEDIUM | **Consent records not included in export.** The `privacy_consents` table is not exported — the data about what consent the founder gave is not part of the compliance export. |

## Cross-Company Awareness Check

The export is scoped to a single `productId`. If Jordan had multiple products, each would need to be exported separately (by switching the active product cookie and re-downloading). There is no "export all my companies" option. No risk of cross-company data leakage in the export itself, but the UX is poor for multi-product founders.

## Verdict: JOURNEY FAILED — Export exists but is critically incomplete for compliance purposes
