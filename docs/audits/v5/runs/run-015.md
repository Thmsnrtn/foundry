# Run 015 — Sam (5-Company Portfolio) on Journey 05 (Remediation PR Review)

## Conditions
Fleet size: 5
Tier: Investor-Ready ($399)
Device: MacBook Pro, Firefox
Network: Office broadband

## Step-by-Step

1. **Sam logs in** → Portfolio view. 5 companies. No indication of which have pending remediations. → Sam cannot triage remediations from this view.
2. **Sam clicks into Company A** → Dashboard. Briefing mentions Atlas opened a PR for rate limiting on the API. Signal sidebar shows "1 open PR" badge in nav (via `open_prs_count`). → Good — the nav badge is visible.
3. **Sam navigates to `/agents/remediations`** → Remediation queue loads. 1 item: "Add rate limiting middleware to /api/* routes." Severity: HIGH. Agent: Atlas. Shows description, affected files, and severity badge. Buttons: Resolve / Dismiss.
4. **Sam clicks the remediation item** → Detail shows what was found, the specific audit dimension (D5: Operational Readiness), and a link to "View on GitHub". → Sam clicks through to GitHub PR.
5. **Sam reviews the PR on GitHub** → Diff is clean. Adds express-rate-limit to API routes. Sensible defaults. Tests included. → Sam approves and merges on GitHub.
6. **Sam returns to Foundry** → Clicks "Resolve" on the remediation item. → POST to `/agents/remediations/{id}/resolve`. Redirects back to the remediation queue. Item gone.
7. **Sam now needs to check other companies for remediations** → Switches to Company B. Navigates to `/agents/remediations`. Empty. → Switches to Company C. Empty. Company D: 1 remediation pending. Company E: 2 remediations pending.
8. **Sam reviews Company D's remediation** → Missing error handling in a Stripe webhook. Medium severity. Sam resolves it via GitHub. → 3 minutes.
9. **Sam reviews Company E's 2 remediations** → One is security (HIGH), one is test coverage (LOW). Sam resolves the security one, dismisses the test coverage one. → 5 minutes.
10. **Total remediation review: ~20 minutes across 5 companies** → 4 remediations reviewed. The overhead was product switching, not the review itself.

## Cross-Company Awareness
Did the user get confused about which company they were acting on? **NO** — Sam was careful to check the product name on each remediation. But the workflow required checking 5 separate remediation queues to find 4 items. A unified queue would have saved 10 minutes.

## Friction Events
- FRICTION-0045: HIGH — No cross-company remediation queue. Sam checked 5 products; 2 had nothing. A fleet-level "all open remediations" view would eliminate the empty-check overhead.
- FRICTION-0046: MEDIUM — Portfolio view doesn't show per-product remediation counts. Sam had to click into each product to discover if there were open PRs. The sidebar badge (open_prs_count) is only visible after entering a product.
- FRICTION-0047: MEDIUM — Resolving a remediation in Foundry doesn't sync the GitHub PR merge status. Sam had to both merge on GitHub and click "Resolve" in Foundry. Two-step process for one logical action.
- FRICTION-0048: LOW — Remediation detail page has good audit dimension context but no link to the specific blocking issue in the audit report.

## Verdict: SUCCESS — all remediations reviewed and acted on, but inefficient
## Would Recommend: Not Yet — "The remediation quality is good. The workflow is bad."
