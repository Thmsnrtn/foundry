## Conditions
Fleet size: 1
Tier: Solo ($79)
Device: MacBook Pro, Chrome, DevTools open
Network: Fast broadband

## Step-by-Step

1. **Morgan checks if Remediation is available** → Navigates to `/products/{id}/remediation`. → Tier gate fires: "Remediation Engine — Automated fix generation and GitHub PR creation. Available on Growth."
2. **Morgan is on Solo ($79)** → Remediation requires Growth ($199). Gate page shows the feature preview: Auto-Fix, GitHub PRs, Re-Audit. → Morgan reads it carefully.
3. **Morgan examines the gate page** → "The Remediation Engine generates targeted code fixes for blocking issues and opens GitHub PRs automatically." → Morgan's question: "What model generates the code? What's the test coverage of generated PRs? What's the revert rate? None of this is disclosed."
4. **Morgan checks Agent Remediations route** → Navigates to `/agents/remediations`. → This route loads (not tier-gated like the product-level remediation page). Shows remediation queue. → **FRICTION**: The agent remediations page loads but shows 0 items because no remediations have been created (remediation creation is gated to Growth+). Confusing: the page exists but is permanently empty on Solo.
5. **Morgan's analysis** → "There are two remediation routes: `/products/{id}/remediation` (tier-gated, shows stats + PR list) and `/agents/remediations` (not gated, shows agent-generated items). The agent route loads but has nothing because the engine that creates remediations is gated. This is an inconsistency."
6. **Morgan decides to upgrade to Growth** → $199/mo. Completes Stripe checkout through Settings. → Tier updated.
7. **After upgrade, Morgan returns to `/products/{id}/remediation`** → Page loads. Remediation summary: 0 PRs (no audit has been triggered post-upgrade yet). → Morgan triggers a re-audit from the audit page.
8. **Audit runs, finds blocking issues** → After audit, remediation engine classifies 2 issues as AUTO-remediable. PRs are created on GitHub.
9. **Morgan reviews the PRs** → Navigates to remediation list. 2 items. Clicks the first: "Add rate limiting to API routes." Shows: what was found, why it matters, audit dimension, severity. Link to GitHub PR. → Morgan inspects the PR on GitHub. Clean diff. Express-rate-limit added. Tests included.
10. **Morgan checks the transparency trail** → Goes to Agent Transparency. Finds Atlas's remediation run. Sees: the prompt that generated the fix (includes the audit finding, codebase context, and generation instructions), the model (Opus), the cost ($0.14), the response (the actual code diff). → "I can see exactly what Atlas was told and what it generated. This is auditable."
11. **Morgan approves and resolves** → Merges on GitHub. Clicks "Resolve" in Foundry. → Next audit confirms the issue is resolved.
12. **Morgan's verdict** → "The remediation quality is high. The transparency is genuine — I can see the full reasoning chain. But the cost transparency is incomplete: I can see per-run cost, but not the total monthly spend on remediation across all agents."

- FRICTION-0087: MEDIUM — Remediation Engine tier gate does not prevent the briefing or agent roster from mentioning remediations. On Solo, agents may reference remediations the user cannot access, creating expectation mismatch.
- FRICTION-0088: MEDIUM — No aggregate cost tracking for remediation. Morgan can see per-run costs in transparency but no monthly or per-product total. No budget controls.
- FRICTION-0089: LOW — After upgrade, remediation PRs don't exist yet until a new audit triggers them. No indication that the upgrade "activated" anything until the next audit cycle.
