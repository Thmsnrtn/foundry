# Run 018 — Riley (15-Company Power User) on Journey 03 (Scaling to 15)

## Conditions
Fleet size: 5 → 15
Tier: Investor-Ready ($399)
Device: MacBook Pro, Arc browser
Network: Gigabit fiber

## Step-by-Step

1. **Riley has 5 companies onboarded** → Each took ~4 minutes (GitHub OAuth, repo select, competitors, audit). Total: 20 minutes for the first 5. Riley needs to add 10 more.
2. **Riley starts batch-adding companies** → Settings → Add Product → Onboarding → repeat. Each cycle: ~4 minutes including audit wait. → **FRICTION**: No batch onboarding. No "add multiple repos at once." Each company is a separate full wizard cycle.
3. **After 3 hours of onboarding** → Riley has 15 companies in Foundry. 15 separate GitHub OAuth flows. 15 separate audit waits. 15 separate competitor entry forms. → Riley is exhausted and irritated.
4. **Riley opens `/portfolio`** → 15 cards in a grid. Sorted by lowest Signal first. → The page is a wall of cards. No visual grouping. No column headers. No aggregate stats bar. Riley must scan 15 cards to find issues.
5. **Riley checks page load time** → Portfolio renders in ~3 seconds. Signal computation runs in parallel for 15 products (`Promise.all`). → Over Riley's 2-second threshold but tolerable.
6. **Riley looks for sorting/filtering** → None. Cards are always sorted by lowest Signal. No way to sort by MRR, risk state, name, or last-updated. No search. No filter by risk state (show me only red/yellow).
7. **Riley looks for batch operations** → None exist anywhere. Cannot "approve all low-risk remediations," "dismiss all info-level signals," or "bulk-resolve decisions."
8. **Riley tries keyboard navigation on portfolio** → Tab cycles through 15 form-wrapped buttons. j/k does nothing. Arrow keys do nothing. → To navigate from card 1 to card 15, Riley must press Tab 14 times.
9. **Riley's assessment** → "This is a list of cards. I need a fleet dashboard with: total MRR, risk state distribution, decision backlog, top stressors across all companies, keyboard nav, and batch actions. What I have is a phonebook."
10. **Riley opens each company's dashboard in a separate browser tab** → 15 tabs. This is Riley's workaround for the missing fleet triage view. → Tabs. In 2026. For a $399/month tool.

## Cross-Company Awareness
Did the user get confused about which company they were acting on? **YES** — With 15 browser tabs open, Riley mixed up Company H and Company J (similar names). Made a decision on Company H thinking it was Company J. The error was only caught because the briefing referenced the wrong product's metrics.

## Friction Events
- FRICTION-0055: CRITICAL — No batch onboarding. Adding 15 companies requires 15 separate wizard cycles, each with GitHub OAuth, audit wait, and form entry. Total onboarding: ~3 hours.
- FRICTION-0056: CRITICAL — Portfolio view at 15 companies is a flat card grid with no sorting, filtering, search, aggregation, or grouping. No fleet summary row. No keyboard navigation.
- FRICTION-0057: CRITICAL — No batch/bulk operations anywhere. Every action (decisions, remediations, signals) is single-product, single-item.
- FRICTION-0058: CRITICAL — No keyboard shortcuts for fleet navigation. j/k, arrow keys, number keys — none work. Tab is the only option, requiring 14 presses to reach the last card.
- FRICTION-0059: HIGH — Portfolio page load: ~3 seconds for 15 companies (15 parallel Signal computations). Exceeds Riley's 2-second threshold.
- FRICTION-0060: HIGH — Riley's workaround (15 browser tabs) defeats the purpose of a unified control plane and introduces boundary confusion.

## Verdict: FAILED — the UI does not function as a control plane at 15-company scale
## Would Recommend: Never — "I have 15 companies. If I can't triage all of them with my keyboard in under 15 minutes, the tool is costing me time."
