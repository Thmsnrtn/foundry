# Foundry Institution

This directory is the durable governing context for Foundry's evolution from an
agent-centric SaaS into an **Adaptive Company Institution**: a system capable of
discovering, understanding, and progressively operating unfamiliar companies.

**It is also the bootstrap.** A fresh capable model should be able to
reconstruct the product, its current verified reality, and the next frontier
from this directory and the repository — without any chat history.

## Start here

1. [`DEVELOPMENT_INSTITUTION.md`](DEVELOPMENT_INSTITUTION.md) — **how development
   operates**: objective, loop, authority, escalation, frontier selection, proof
   standard, checkpoint protocol.
2. [`AUTONOMOUS_CAMPAIGN_STATE.md`](AUTONOMOUS_CAMPAIGN_STATE.md) — **live
   frontier**: verified checkpoint, active work, blockers, next start.
3. [`IMPLEMENTATION_STATE.md`](IMPLEMENTATION_STATE.md) — **current verified
   reality**: what exists, what is reachable, what is proven, what is not.

4. [`PROOF_PROGRAM.md`](PROOF_PROGRAM.md) — the **E0–E6 evidence ladder** that
   every maturity claim in this directory uses. Short, and nothing else here
   parses correctly without it.

`IMPLEMENTATION_STATE.md` carries the commands to run the suite and gates, and
a concept → code index. Read the rest when the work touches it.

## Rules for this directory

Existing code and older design documents describe implementation history; they
do not override this institution.

Update current truth when evidence changes — replace a false claim rather than
appending a newer paragraph beneath it. Amend the doctrine documents
deliberately when the governing theory changes, never merely to rationalize
current code. Do not add a document unless no existing one cleanly owns the
contract.
